# Phase 07.2 Plan 15: Antigravity CLI harness adapter Summary

**Gemini 3.8 Flash (`gemini-flash`) and GPT-OSS 120B (`gpt-oss`) now run as `reverseapoc drive` arms through `agy -p --output-format stream-json` on the owner's Google AI Plus sign-in. Each session runs in its attempt dir under a driver-written settings file in build/ that allows only the wrapper forms, the session's own files and reads inside the attempt dir, and denies orig/, third_party/, `..` and 8.3 short-name paths and unsandboxed commands. A post-session audit reads agy's own stream (commands, writes, reads), the settings bytes and the attempt dir against the wrapper ledger. A quota canary with six probes plus `agy -p /usage` must PASS on the installed CLI before any night, and it names the OpenRouter fallback arm when AI Plus gives no quota. CLAUDE.md and workflow.md extend the one runtime exception to Antigravity.**

## Accomplishments

- **Arms (D-25, D-25a, RULINGS).** `gemini-flash` and `gpt-oss`: harness `agy`, backend `google`, the exact slugs from the owner's `agy models`, `accepted_init` the slug, prices 0, one worker, `sends_disassembly = true`, co-author lines. `gemini-3.8-flash-openrouter` is D-21's paid fallback (Claude harness, OpenRouter, `OPENROUTER_API_KEY`; id and prices are marked assumptions). No Gemini Pro arm.
- **Session env (RULINGS token-leak guard).** Codex and agy share `backends.SIGNED_IN`. Each loses every `ANTHROPIC_*`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`, every arm key and every Google key variable.
- **argv and prompt.** `build_agy_argv` is pinned token for token: stream-json, `--model`, `--sandbox`, `--add-dir`, `--settings`, `--disable-slash-commands`, `--print-timeout`, then `-p` and the prompt last. The flag that skips permissions is never passed. `agy_prompt` is `codex_prompt`'s body.
- **Stream (agyjson).** It uses streamjson's own parser. `init_problems` checks the cwd, the model and that the permission mode is no bypass, and it is a STOP condition. Usage takes input, output plus thinking, cache read, `num_turns` and `duration_seconds`. Commands, writes and reads are counted once per step, without denied steps. `denied_actions` gives `action(target)` strings. `failure` and `classify` are included.
- **Guard set.** The settings JSON goes under `build/driver/<run>/agy/`, outside the workspace, and is never written to the owner's settings. The wrapper ledger is the Codex one. `_strays` sends every non-Claude harness through `_signed_in_strays`, which uses one audit with harness-specific inputs. An unknown harness counts as a stray.
- **Canary and gate.** The canary checks: a clean init and a SUCCESS result; a refused outside write; a denied or failed network command; a denied unsandboxed command; four orig/ probe reads denied (`../`, `ORIG`, `..` behind the attempt-dir prefix, `THIRD_~1`; the probe file never exists); the wrapper check at exit 0 with its consumed note; the attempt dir matching the ledger; and the settings file unchanged. Then come the quota step and the usual containers, tree and refs lines. The pass file records the CLI version, the date, the tokens and the quota. `refuse_unproven` gates every non-Claude harness and refuses one it has no canary for.
- **Policy and docs.** CLAUDE.md and workflow.md now say that Codex CLI (ChatGPT Plus) and Antigravity CLI (AI Plus) may run `reverseapoc drive` sessions, for spike 012 and later multi-arm nights. No `.codex/`, `.gemini/` or AGENTS.md is committed. docs/legal.md has the removable D-24 user-global note. docs/model-routing.md has an "Antigravity arms" section.

## Concerns for the owner's canary (unverifiable offline; open, not built)

- **Stream field names.** `step_update.tool_info.{command,path,exit_code}`, the tool names (`write_file`, `read_file`, `run_command`), the `denied_actions` entry shape and the `permission_mode` value come from docs, not a captured run. If they differ, the audit and canary fail closed: the audit sees unknown data as strays, and missing denials are FAILs.
- **Rule syntax.** Whether agy accepts `read_file(regex:...)`, `write_file(<abs path>)`, `**` globs and `unsandboxed(regex:.*)`, and whether it normalises `..` before matching, is unconfirmed (A9). The four probe reads exist to show it.
- **Tool steps with neither a command nor a path** (for example a web or search tool) are not judged by the audit. Headless agy should soft-deny them, since they are not allowed.
- **`/usage` format (A8).** If it prints nothing machine-readable, the canary PASSes with an estimate, and the owner sizes the arm by hand.
- **8.3 paths.** If the checkout itself sat under a short-name path, the short-name deny rule would deny the session's own files. This fails closed, and docs/model-routing.md says so.
- **`agy -p /usage` and `agy --version`** run through `Seams.run` with the driver's own environment, not the stripped session env, as Codex's `--version` does. Neither starts a model session.
- **`--print-timeout`** is passed in whole seconds. Whether agy wants another unit is unconfirmed.
