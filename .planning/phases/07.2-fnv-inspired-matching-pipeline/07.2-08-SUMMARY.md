# Phase 07.2 Plan 08: Base-vs-head match check Summary

**`reverseapoc compare-objects` compares two compiles of a unit by segment bytes, relocations and public offsets with names resolved to addresses, and the disabled, label-gated `match.yml` runs it on a pull request's touched units inside the image with no network, main's tools and the PR as data.**

## Accomplishments

- `compare_objects.compare(base, head, *, base_symbols, head_symbols)`: segment layout (index, name, class, use32), lengths and bytes; each fixup's offset, size, mode, location, frame method, target and displacement, with an extern target resolved through its tree's SymbolTable (text fallback for a name no table knows), a segment or group target by name; backpatch offsets; publics as (segment, offset, local, resolved address). THEADR and COMENT 0xE9 are never read. COMDATs and fixups into iterated data raise CompareError.
- The verb `reverseapoc compare-objects` in the `_cmd_stats` shape: text `same: ...` or `differ: _TEXT+0x9: code bytes: 1 of 12 bytes differ`, or `--json`; exit 0, 1 or 2 (`reverseapoc compare-objects: error: ...`).
- `.github/workflows/match.yml`: off until `vars.MATCH_CHECK_ENABLED == 'true'`, main's workflow only, the `match-check` label for a labeled run, a pin that fails a head that moved after the label, the path allow-list since the merge base, refusal of new, removed or linked units, then per unit two `reverseapoc cc` runs and one `compare-objects` run, all through one `docker run --rm --network none` helper with read-only mounts and no game files.
- `docs/ci.md`: what the check proves and does not, the allowed paths, how a maintainer runs it, the owner-only runner setup (8 steps), the off switch, and the security model against GitHub's `pull_request_target` and self-hosted runner guidance.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] The path allow-list admits the two symbols.csv files**
- **Found during:** Task 2
- **Issue:** The plan's allow-list is `src/**` and `*.md`, but a rename-only PR has to add the new name's row to `config/<exe>/symbols.csv`. Without that row, the head tree cannot resolve the new name, so the compare would fail. A list without symbols.csv makes D-08's "rename-only passes" impossible, and the plan's own `--head-config head/config` would have nothing to read.
- **Fix:** `config/ufo2p/symbols.csv|config/tacp/symbols.csv` are allowed beside `*.md`. The src rule is narrowed to `^src/(ufo2p|tacp)/[a-z0-9_]+\.c$`. Both are pinned by `test_match_refuses_other_paths` and documented in docs/ci.md. symbols.csv is read only as names and addresses by main's SymbolTable, and a malformed one exits 2.
- **Files modified:** .github/workflows/match.yml, tests/test_workflows.py, docs/ci.md
- **Commit:** 55700b4f, 7d5ca35d

**2. [Rule 1 - Bug] The compile outputs live inside the container's repository root**
- **Found during:** Task 2
- **Issue:** `reverseapoc cc` refuses an object outside its repository root (`guest_path(..., inside=True)`), so "outputs under the runner's temp directory" cannot be a plain temp path.
- **Fix:** `$RUNNER_TEMP/match` is mounted at `/work/build/match`. The objects sit in the runner's temp directory on the host and inside the root in the container. The checkout is mounted read-only, and the gate stamp write under `build/cache` fails quietly by design (`_write_stamp` is best effort).
- **Commit:** 55700b4f

**3. [Rule 1 - Bug] The head compile mounts head/src over src/**
- **Found during:** Task 2
- **Issue:** Compiling `head/src/<exe>/<unit>.c` would select the cflags rule by the path `head/src/...`, which only the `*` default matches. A unit with its own flag rule (the -oneatx rows) would compile with the wrong flags at head.
- **Fix:** The head compile adds `-v "$GITHUB_WORKSPACE/head/src:/work/src:ro"` and compiles the same `src/<exe>/<unit>.c` path. Both sides then use main's rule for that path, as D-08 asks.
- **Commit:** 55700b4f

**4. [Rule 2 - Missing critical] Fail-closed additions in compare-objects and match.yml**
- compare-objects refuses COMDATs and fixups into iterated data (the reader drops those fixups' targets), so neither can pass unseen. It also compares the module's memory model and default libraries.
- match.yml requires `github.ref == 'refs/heads/main'` and pins the labeled head SHA. It refuses new, removed and symlinked units. The base commit reaches the head repository by a local fetch of the workspace's HEAD, checked against `BASE_SHA`.
- **Commit:** 40a16eb8, 55700b4f

**5. [Rule 1 - Bug] The data placeholder name in the rename test**
- The plan's example names `D_000C1000` / `frame_wrap`. Watcom links data as `_D_000C1000`, and a symbols.csv data name needs its leading `_` (`unitdefs.c_name_of`), so the tests use `_D_000C1000` / `_frame_wrap`.

**Total deviations:** 5 (2 bugs in the plan's compile path, 1 in its example names, 2 missing-critical). **Impact:** deviation 1 widens the judged paths by two data-only files. The owner should confirm it (see Concerns). The rest keep the plan's contract.
