# Phase 07.2 Plan 06: The spike 012 harness Summary

**Six drive flags for spike 012 (D-17).** `--night-model` picks the night's Claude model. `--picks FILE` freezes the list through `TierQueue.only`. `--dry-run --stratify A,B,C --write-picks` writes a size-stratified pick list. `--hold` runs without landing anything, each function once, as `hold_run`/`HOLD_EXACT` records under a `HELD` marker. `--land-held RUN...` lands each exact function once, from the cheapest arm, through the night's own `_judge` → `_gate_matched` → `_commit_match` path, with a landing record and no second attempt record. Hold runs are kept out of passes, packs and the default stats report.

## Accomplishments

- **cli.py:** the six flags. `_stratify` parses `A,B,C`. `_run_name` accepts a run id with an optional trailing `*`. `HARNESS_FLAGS_REFUSED` and `_harness_conflict` form one refusal point, checked before `--model`'s rule. `--canary --night-model X` makes the canary ask for X.
- **driver.py, options:** `DriveOptions` gains `night_model`, `picks`, `stratify`, `write_picks`, `hold` and `land_held`. `DriveConfig` gains `night_model`, `hold` and `land_held`. `_model` returns the night model on a matching night, and the budget stays `budget_for`.
- **driver.py, picks:**
  - `read_picks` checks each line (exe, `0x` plus 8 hex digits, no extra text, no duplicate) and names the line number when it refuses.
  - `restricted_keys` is the Fable trial's set, the picks set, or both intersected. `real_deps` and `restricted_picks` (the renamed `fable_trial_picks`) use it.
  - `refuse_picks` refuses, before anything else runs, every pick that is not a queue member or is already matched, and names them all.
- **driver.py, hold:**
  - `_hold_counted` resets the unit and records the session. The outcome is `HOLD_EXACT` when a plain check exited 0 (`exact_source`), else `PARTIAL` or `GAVE_UP`.
  - `_salvage` resets a LIMIT session unjudged.
  - `_hold_done` counts the pass. The coordinator then parks the key in the tier queue, so each function runs once and its callers still follow.
  - `HELD` is written at run start, and console lines say "hold run".
- **Exclusions:** `pass_index` skips hold-run records. `attempt.earlier_notes` skips run directories that hold `HELD`, and skips `hold_run` records together with their give-ups and best C; gzw's cache key follows. `stats.collect` leaves hold-run attempts out of the default report, and `--run` keeps them.
- **Stratify:** `STRATA = ((0, 64), (64, 256), (256, None))` and `STRATIFY_PREVIEW = 400`. `stratified_picks` reads unattempted tier picks in queue order and sizes them with `stats.read_sizes`. It refuses with every short group named. `write_picks` writes the RULINGS format with `#` header lines.
- **Land-held:**
  - `_Night.land_held` keeps the cheapest `HOLD_EXACT` per function (cost, then run id, then attempt), skips matched functions, and lands in exe, unit and start order.
  - `_land_one` copies the latest exit-0 `checks/NNNN.c` into a fresh view under the landing run. It refuses a unit or `include/` changed since the view head, then runs `_judge`, `_gate_matched` and `_commit_match(held=...)`.
  - The commit message carries the held attempt's figures and the hold run's name, and the co-author line of its requested model.
  - `_record_landing` writes the record. The undo path writes a REFUSED landing.
  - `refuse_land_held` makes the verb exit 2 when no name matches a hold run.
- **docs/model-routing.md:** what each flag does, the hold-run marker, the spike 012 command order (7,7,6 and the six rows of 256 B and up), the land-held rules (credit, cheapest rule, stale-unit refusal), the refusals, and the fact that the dry run's `held:` still means the signed asm hold.
