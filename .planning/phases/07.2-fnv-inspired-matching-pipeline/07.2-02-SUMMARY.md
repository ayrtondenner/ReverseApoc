# Phase 07.2 Plan 02: Structured give-up records Summary

**A matching session's `giveup.json` beside notes.md, validated by `attempt giveup` (a matching-only form in `hooks.MATCHING_FORMS`) and again by the driver into the schema-3 record's `giveup` with `best_code`. The next context pack shows "Earlier give-ups" and the "Earlier best C" (the best earlier attempt's definition), both inside the 24 KB cap and in gzw's cache key.**

## Accomplishments

- hooks.py: `GIVEUP_NAME`, `MATCHING_FORMS`, `forms_for(kind)`. `attempt_form_matches` takes the forms, and `bash_allowed` and `matching_write_allowed` take the session kind. The matching layer's Bash branch reads the kind from `REVERSEAPOC_SESSION_KIND`, and its deny message lists that kind's forms. The always layer exempts the notes file's giveup.json sibling only. `_BASH_CHARS` is unchanged.
- attempt.py: `GIVEUP_CATEGORIES` now lives here, and `driver.GIVEUP_CATEGORIES` is the same object. `read_giveup` checks exactly four keys, the nine categories, and texts that are non-blank, at most 200 characters, with no `{`, `}`, `;` and no hex run of 65 or more. Each refusal names the field. `cmd_giveup` refuses a readability claim and prints the accepted category and the three texts. It reserves no check and runs no container.
- cli.py: `attempt giveup` (metavar `{check,asm,context,giveup}`). The form check uses `forms_for(kind)`.
- driver.py: `_giveup` re-validates `<attempt dir>/giveup.json` for a matching session and adds `best_code`. A refusal records null and prints one console line. The audit's allowlist now gets the session kind.
- contextpack.py: `TITLE_BEST_C` comes after the draft and `TITLE_GIVEUPS` before the notes, with `Notes.giveups` and `Notes.best_c`. The cut order is look-alikes, best C, callers, draft, records, give-ups, texts, and the header and `truncated` name each cut. Added `one_line`, which `Neighbour.line` now uses too.
- attempt.earlier_notes takes the give-up lines from the committed records (`<run> attempt <n>: <category>; still differs: ...; suspected: ...; best <best_code>`). The best C comes from the highest-percent record (ties go to the latest) whose `best/<unit>.c` defines the record's C name. Both reach `_notes_digest` through `Notes`, so the cache key covers them.
