# Phase 07.2 Plan 13: Codex CLI harness adapter Summary

**GPT-6 Luna and GPT-6.1 Sol now run as `reverseapoc drive` arms through `codex exec --json` on the owner's ChatGPT login. A per-session rules file under build/ allows only the attempt wrapper. A post-session audit checks every command, every file_change and the attempt dir against a wrapper hash ledger kept outside the workspace, then quarantines any stray and stops the night. A Codex canary probes identity, outside writes, the network and a compound command, and no Codex arm runs until that canary has passed on the installed CLI. CLAUDE.md and workflow.md name this as the one scoped runtime exception.**

The model ids and the co-author address are marked as assumptions to confirm at setup. `load_arms` refuses `base_url`/`key_env` on a non-Claude harness and allows an empty init list only there.
- **Session env (D-12, RULINGS token-leak guard).** A Codex session loses `OPENAI_API_KEY`, `OPENAI_BASE_URL`, every arm's key variable, every `ANTHROPIC_*` name and every `GOOGLE*/GEMINI*` key or credentials name (case-insensitive).
- **argv and prompt.** `build_codex_argv` is pinned token for token. It uses workspace-write with `--cd` set to the attempt dir, network off, approval never, `--ignore-user-config`, `--ephemeral` and the attempt dir trusted, with the prompt last. - **Stream.** `codexjson` reuses streamjson's `parse`. It sums turn usage: cached input counts as cache read, reasoning tokens are added to output, and duration is the wall clock. It lists commands once per item (a started-only item included), lists `file_change` paths, and gives failure text, a disposition, and each execution's output and exit code for the canary.
- **Driver.** `_launch` picks the argv by the arm's harness. Codex sessions skip the init check, and the record keeps `model` and `cli_version` null with `model_requested` set.
- **Guard set.** At launch the driver writes `.codex/rules/attempt.rules` and an empty ledger under `build/driver/<run>/ledger/`, and passes the ledger in `REVERSEAPOC_WRAPPER_LEDGER`. The wrapper appends `{path, sha256}` for the check lock, the reserved C, the saved JSON, the note, checks.jsonl, context.md and cache entries. It refuses a ledger inside the attempt dir or outside build/driver/, and a failed append is exit 2. After the session `_strays` adds the Codex audit, which is never routed through the Claude transcript reader.
- **Canary and gate.** The Codex canary checks, in order: whoami against the owner's `USERNAME`; the outside file absent; the fetch failed; the compound file absent; the wrapper check logged exit 0 and consumed its note; the audit flagged the three probes; a ledger-clean attempt dir; plus the usual containers, tree and refs lines. It writes `build/driver/canary/<arm>.json` with the `codex --version` result. A Codex night without a PASS for that version exits 2 and names the canary command.
- **Policy and docs.** Both rule files keep "only agent runtime" with one exception, written plainly. docs/model-routing.md gains "Codex arms": the session, the login, the guard set, the audit and its residual risk, the canary, the pass gate, the Plus windows, the Windows caveats and the owner-installed rules fallback.

## Security review findings (orchestrator, mid-plan)

1. **[HIGH] `_strays` did not audit Codex.** It applied as committed at `a895d685`: Task 2 had not landed yet, and RED 2 shows it. Fixed in `79210a8b`. For a Codex claim, `_strays` reads `codexjson.commands` and `codexjson.write_targets` and the attempt-dir inventory against the ledger, never `_write_targets`.
2. **[HIGH] EGRESS_ENV does not bind Codex reads.** This applies. No Codex sandbox read restriction is used: none could be confirmed offline without running the real `codex` (forbidden here) or the network. The fix is detection. Any command naming `orig` or `third_party` as a path part, in any spelling (case, either slash, quotes, drive, `..`), is a stray, and so is any `file_change` naming one. Every non-wrapper command is a stray anyway. docs/model-routing.md states the residual risk plainly: detection after the fact, not prevention. The scratch-copy prevention (running Codex in a copy outside the checkout) was not built. It would move the view, the wrapper's ROOTS and the container mounts, which is more than this plan's scope (recorded as a follow-up below).
3. **[MEDIUM] Trusted `.codex/` inside the writable root.** This applies. Each launch gets a fresh attempt dir (`_fresh_dir` moves the old one aside), so the rules file is recreated by the driver every launch. Any session write under `.codex/` is a stray: a new `config.toml` because it is not an allowed file, and a changed or removed rules file because it differs from its launch hash. It is quarantined and the night stops. `test_audit_quarantines_a_session_written_codex_config` shows a session-written `.codex/config.toml` is quarantined and no later launch happens. What stays open: if Codex re-read a session-edited rules file or config within the same session, only the after-the-fact audit would catch it.
4. **[MEDIUM] Linked cache ancestor.** This applies, and it was worse than reported: the containment moved a file out of the junction's target. Fixed in `65cf1689`. `view`, `view/build` and `view/build/attempt-cache` are each checked with `_is_link` before the walk. A linked component goes into the inventory as a link and is treated as a stray, nothing behind it is read, and a cache that resolves outside the attempt dir is a stray too. The quarantine now removes a junction or directory link itself (`_remove_entry`), never its target. A linked `view` is tested as well (a junction on Windows).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `codexjson.classify`, then `codexjson.executions`**
- **Found during:** Task 1, then Task 3
- **Issue:** `_Session.disposition` runs streamjson's Claude classifier, which calls a session with no `result` event TRANSIENT, so no Codex session could be counted. The canary also needs each command's output and exit code.
- **Fix:** A Codex classifier (documented in the module), and `executions(events)`. `commands()` is now built on `executions()`.
- **Commits:** a895d685, 91e28b1a

**2. [Rule 2 - Security] A file_change to a wrapper-owned file is a stray**
- **Issue:** The plan allows write targets that are "wrapper-owned". An agent edit of checks.jsonl would then be vouched for by the wrapper's next ledger entry.
- **Fix:** Write targets must pass the session's allowlist only. Wrapper output is proven by the inventory and ledger alone.
- **Commit:** 79210a8b

**3. [Rule 2 - Security] Ledger placement validated and truncated at launch; check lock, context.md and cache ledgered**
- **Fix:** The wrapper refuses a ledger in the workspace or outside build/driver/. The driver empties it at every launch. The plan's list of ledgered files is extended to every file the wrapper writes. `test_wrapper_ledger_must_lie_outside_the_attempt_dir` and `test_a_failed_ledger_append_is_an_error` were added.
- **Commit:** 79210a8b

**4. [Orchestrator] Security findings 1-4** (above). Findings 1-3 were folded into Task 2. Finding 4 got its own RED/fix pair after Task 3.

**5. [Placement] A failed Codex canary writes `result: FAIL`**
- **Issue:** The plan says "write no pass file" on FAIL. An earlier PASS for the same version would then survive a failed canary.
- **Fix:** FAIL overwrites the file. The tests accept "absent or not PASS".

**6. [Test bug] Each night helper call runs the real `driver.drive`**
- **Issue:** A second `codex_night` call in one test captured the first call's monkeypatched drive.
- **Fix:** `REAL_DRIVE` is captured at import. It shipped in the Task 2 GREEN commit 79210a8b, together with three line-length fixes in the tests.

**Total deviations:** 6 (1 blocking, 2 security, 1 orchestrator set, 1 placement, 1 test bug). **Impact:** scope unchanged. The audit is stricter than the plan asked.

## Concerns for the owner's canary (RESEARCH A4-A7, unverifiable offline)

- **Shell-wrapped commands.** Codex may report a command wrapped in its shell, for example `powershell.exe -Command '...'` or `bash -lc '...'`. The audit then flags every wrapper call as a non-wrapper form and the canary FAILs. It fails closed, and the canary output shows the exact form if a narrow unwrap is needed later.
- **The trust entry.** `-c projects."<attempt dir>".trust_level="trusted"` uses a JSON-quoted path whose parts contain dots (`.claude`). Whether Codex's `-c` dotted-key parser accepts it is A5. If the rules do not load, the fallback in docs/model-routing.md applies.
- **Approval key.** `approval_policy="never"` via `-c` is A4.
- **Token mapping.** Adding `reasoning_output_tokens` to output assumes Codex reports them apart from `output_tokens`. Confirm against the first real stream.
- **EGRESS_ENV.** `REVERSEAPOC_EGRESS=1` is still set in a Codex session, by 12's env builder for every non-Anthropic arm. Nothing in Codex reads it, so it is harmless.
