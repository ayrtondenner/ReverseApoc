### WR-06: `--land-held` landed at most one held function per unit

**Files modified:** `tools/reverseapoc/driver.py`, `tools/reverseapoc/contextpack.py`, `tools/reverseapoc/flags.py`, `docs/model-routing.md`, `tests/test_drive.py`
**Commits:** 0d1a3021 (RED), 6f9645f8 (a test helper call the RED commit got wrong; the test still failed at RED on `matched 1 != 2`), 29e17a52 (fix), f4f06e1b (docs)
**Why the second was stale:** `_stale_reason` ran `git diff --quiet <view head> HEAD -- <unit>
include`. The first landing's own match commit changed the unit, so the second function always
read as stale.
**Applied fix:**
- `land_held` keeps `bases`: per unit, HEAD as it was before this run's first landing of that
  unit (recorded only when that landing matched).
- For a later function of the same unit, `_stale_reason` judges two ranges:
  - the unit and `include/` between its view head and that base;
  - `include/` between that base and HEAD.
- So only this run's own landing is not a change. The real stale case still refuses:
  `test_land_held_still_refuses_two_functions_of_a_unit_changed_elsewhere`, plus the existing
  `test_land_held_refuses_a_changed_unit`.
- `_held_text` then splices only the held function's definition onto HEAD's unit, keeping the
  first landing. A splice that is impossible is REFUSED and named.
- The splice is flags' existing `_spliced`, moved to `contextpack.splice_definition` because
  driver cannot import flags (flags imports driver). flags now aliases it, and test_flags and
  test_contextpack pass unchanged.
- `test_land_held_lands_two_functions_of_one_unit`: both MATCHED, two gates, and the final unit
  defines both.

**Human verification:** this is landing logic. Confirm that the base-then-HEAD judgement and the
definition-only splice are what the owner wants for a real spike, for example a second held
attempt that also added a file-scope declaration. Its splice drops that declaration, so the gate
would refuse it.
