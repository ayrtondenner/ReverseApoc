# Phase 07.2 Plan 03: Plan and notes on every check Summary

**A matching `attempt check` now refuses (exit 2, no check used) without a valid plan.json and a check-note.json beside notes.md. After each run, the wrapper itself writes checks/NNNN.note.json, holding the agent's change, why and expect plus the observed exit, objdiff %, bytes differing, first_va, the window's first row and the region summary. `attempt plan` validates the plan against D-03 on its own. The canary writes both files and probes a forbidden session-file write.**

## Accomplishments

- hooks.py: `PLAN_NAME`, `CHECK_NOTE_NAME` and `SESSION_FILE_NAMES` sit beside `GIVEUP_NAME`.   - `read_plan(path, size)` checks for exactly frame, slots, calls and regions.   - `read_check_note(path)` takes exactly change, why and expect, each at most 400 characters, and refuses `observed` by name.
  - The refusal sits in `_locked_check`, after the budget test and before `_reserve`.
  - `checks/NNNN.note.json` is written with O_EXCL and gets the observed fields. `CheckLogLine.note` is a new default field after the readlint fields (ruling F11).
  - `cmd_plan` is the new verb.
- cli.py: `attempt plan` sits beside giveup (metavar `{check,asm,context,giveup,plan}`).
- driver.py: `CANARY_PROMPT` now has eight steps: two forbidden Writes, `ls`, context, the forbidden giveup.json, plan.json, check-note.json, then the check. `canary_prompt` fills in the absolute attempt-dir paths and a plan sized from functions.csv through `attempt.claimed_row`. `_check_evidence` requires the consumed note, and `CANARY_DENIED` now holds the session-file probe.

## Deviations from Plan

**1. [Rule 1 - Spec conflict] D-03's "one region is enough under 64 B" is enforced, so the canary plan helper is not "one region under 256 B"**
- **Found during:** Task 1, designing `read_plan`
- **Issue:** The plan's action for `_canary_plan_text` says "one region 0..size under 256 B". CONTEXT D-03 (a locked owner decision) says one region is enough only under 64 B, and the plan names `PLAN_SMALL_SIZE = 64`. As written, the constant would do nothing.
- **Fix:** From 64 B, `read_plan` requires two regions. A row of exactly 0x100 bytes is the exception, because the grid rule leaves no room for an inner boundary there. `_canary_plan_text` (and the test helper `_plan`) give one region under 64 B, two halves from 64 B, and one region per 0x100 from 256 B. The real canary row is 13 B, so its plan is a single region anyway. `test_canary_plan_is_valid_at_every_size` pins the helper over eight sizes.
- **Committed in:** 937ca841

**2. [Rule 3 - Blocking] The canary rig needed a functions.csv**
- **Found during:** Task 2
- **Issue:** The canary now reads its row size before the session, and the test rig's checkout had no config/ufo2p/functions.csv.
- **Fix:** `_canary_rig` commits a made-up row of 13 bytes for func_000A3980 next to the unit. If the driver cannot read the row, it refuses the canary before the session ("canary row").
- **Committed in:** 815e578e (rig), 937ca841 (driver)

**3. [Rule 1 - Refactor inside GREEN] `read_giveup` shares the new helpers**
- **Issue:** The plan and the note need the same steps as the give-up: one JSON object, then exact keys.
- **Fix:** `_giveup_doc` became `_session_object` plus `_exact_keys`. 02's give-up tests pass unchanged.
- **Committed in:** 937ca841

**Total deviations:** 3 (1 spec reading, 1 blocking, 1 refactor). **Impact:** no scope change. Deviation 1 is stricter than the plan's helper text, and the reason is recorded here for the verifier.
