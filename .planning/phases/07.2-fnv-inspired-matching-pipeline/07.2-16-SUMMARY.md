# Phase 07.2 Plan 16: Multi-arm drive Summary

**`reverseapoc drive --arm NAME=WORKERS [--arm ...]` now runs several model arms side by side in one drive process, keeping one drive lock, one audit and one commit queue. Each arm runs under its own run id `<run>-<arm>`, with its own pick queue over the same frozen picks, its own usage-limit pause and its own caps (its `max_workers`, an optional `max_sessions`). So under `--hold` each function is attempted once per arm, and a Codex window or the Antigravity quota pauses only its own arm. `--night-model X` stays the one-arm shorthand. `stats --run` splits the results by arm (`backend/harness/model`), and `--land-held <run>-*` lands each function once from the cheapest arm.**

## Accomplishments

- **cli.py.**
  - `--arm NAME=WORKERS` (`_arm_spec`: a backends.toml arm and a whole number of 1 or more), repeatable. `--night-model X` becomes `arms=((X, --workers),)`, and with `--arm` the workers are the sum.
  - `_arm_conflict` refuses an arm named twice, and `--arm` with `--night-model`, `--workers`, `--fable-trial`, `--canary` or `--session readability`. `--land-held` refuses `--arm`. `--allow-egress` may name any arm of the night.
  - A small `_Given` action marks `--workers` as given, so its shown default of 3 stays.
- **driver.py, lanes.**
  - `DriveOptions.arms`, `DriveConfig.arms` and `night_arms(options)`.
  - `_Lane` holds one arm's state: its arm name, its run id (`<run>-<arm>` with several arms, the base run id with one), its worker numbers, its pause, its session cap and counts, its passes, `done` set, deferred picks and queue.
  - `night.lane` is the worker thread's lane. `_model`, `_arm`, `_claim`, `_claimed`, `_pass`, `_function`, `_park`, `_hold_done`, `_label` and the limit record all read it.
- **driver.py, coordinator.**
  - Each lane gets its own queue from `Deps.queue` (a fresh tier queue or pool generator), bound to its own passes.
  - `_next` asks the lanes in turn. Each lane's lowest free worker takes that lane's next eligible pick. `busy` stays keyed by `(exe, unit)` across all arms, and a night ends when every lane is finished.
  - A MATCHED pass drops the function from the other lanes (`_Lane.drop`).
- **driver.py, pauses and caps.**
  - Each lane has its own `_Pause`, and `night.pause` is the first lane's.
  - `_reserve` holds the night's `--max-sessions` and the arm's own `max_sessions`, counting on both. `_settle` replaces the three copies of the slot bookkeeping.
  - An arm at its cap is skipped by the coordinator and counts as finished.
- **driver.py, gates and records.**
  - `refuse_arms` runs per arm: the name is in the table, workers are within `max_workers`, `backends.refuse_stray_egress` passes over the night, and `preflight` passes with the arm's own `--allow-egress`.
  - `refuse_unproven` loops over `night_arms`, so every Codex or agy arm needs its own canary PASS.
  - Under `--hold` every arm run directory gets the HELD marker.
  - `_night_totals` counts the records of the base run and of every arm run. The run record's `workers` is the night's total.
  - A multi-arm night prints one `arms:` console line, and each attempt line names its arm.
- **backends.py and backends.toml.** `max_sessions` is an optional whole number of 1 or more (`_count`, shared with `max_workers`). It is 20 on `gemini-flash` and `gpt-oss`, with the comment that the owner sizes it from the agy canary's quota. `refuse_stray_egress` was added. The missing-egress message now names both `--night-model` and `--arm`.
- **stats.py.**
  - `arm_key` is `backend/harness/model`. v1 and v2 records fall under `anthropic/claude/<model>`.
  - `by_arm` gives per arm the distinct functions attempted, matched (attempts and landings credited to the arm) and held exact, plus tokens and cost.
  - `by_model_size` is keyed by arm, and the text shows "per arm" and "per arm and size" blocks.
- **docs/model-routing.md.**

## Deviations from Plan

**1. [Interface shape] One arm keeps the base run id.** The plan says each arm runs under `<run>-<arm>`, and also that `--night-model X --workers 2` behaves exactly as `--arm X=2` with 06's tests unedited. Both hold only if a one-arm night keeps the base run id, so `<run>-<arm>` applies when the night has several arms. One arm cannot share an attempt directory with another (Pitfall 7 needs two). Pinned by `test_night_model_is_one_arm`.

**2. [RULINGS] The local arm is `qwen-local`.** The plan's `qwen3.6-35b-a3b-local` was renamed in 07.2-12 per RULINGS, so the tests use `qwen-local`.

**3. [Rule 2 - Correctness] A match on one arm drops the function from the other arms.** This is not in the plan. Without it, on a night without `--hold`, a second arm would attempt a function the first arm had just landed. `_Lane.drop` is three lines, and under `--hold` it never fires.

**4. [Rule 2 - Security] `--canary` is refused with `--arm`.** The plan's refusal list does not name it. A canary proves one arm (`canary_model`), so `--canary --arm ...` would have silently ignored the arms.

**5. [Rule 2 - Missing critical] Every per-arm gate got its own multi-arm test** (orchestrator instruction): the canary pass (Codex and agy), `--allow-egress` per arm, the token-leak guard, the per-arm session env, `max_workers`, and the Codex audit stopping a multi-arm night.

**6. [Rule 1 - Bug] A test helper shadowed an existing one.** Task 2's RED commit added `_until(predicate)` to test_driver_workers.py, which already had `_until(*events)`. That broke `test_a_later_sessions_baseline_never_restores_anothers_stray`. It was renamed `_poll` in Task 2's GREEN commit, together with two lines ruff found too long.

**7. [Placement] The per-arm caps are in Task 1's refuse_arms.** The `max_workers` refusal per arm landed with Task 1's gates, so Task 2's `test_arm_caps` re-pins it, and its `max_sessions` and night-cap parts are what drove Task 2.

**8. [Process] A docstring edit during a pytest run.** I edited driver.py's module docstring while the first full suite was running, which breaks the gzw rule ("no package edit while pytest runs"). That run passed, but it does not count. The docstring commit also left a 101-column line, which ruff caught, so `633c4541` re-wrapped it. The full suite then ran again on the final bytes (Verification).

**Total deviations:** 8 (1 interface shape, 1 RULINGS name, 3 missing-critical or security, 1 test bug, 1 placement, 1 process). **Impact:** scope unchanged. The refusals and the cross-arm match rule are slightly stricter than the plan asked.
