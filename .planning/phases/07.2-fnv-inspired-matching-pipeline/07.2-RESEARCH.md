# Phase 07.2: FNV-inspired matching pipeline - Research

**Researched:** 2026-11-09
**Domain:** Python matching tooling (driver, attempt wrapper, hooks, check, readlint, stats), agent harness routing
(Claude Code, Codex CLI, Antigravity CLI, Anthropic-compatible backends), GitHub Actions CI
**Confidence:** HIGH for the in-repo code facts (read this session, cited file:line); MEDIUM for the external CLIs and
backends (official docs read this session, behaviour not exercised); LOW where marked `[ASSUMED]`

## Summary

Every item of this phase extends code that already exists, and the code has firm invariants the plans must keep: an
exact key-set record validator with an additive-shape precedent (gzu's `_totals_shape`), a hook whose Bash rule
admits only `[A-Za-z0-9_ -]` characters and exact argv forms, a driver audit that reuses the hook's write allowlist,
and skill tests that require every wrapper form to be quoted in both skills. The three findings that change the plan
shape most:

1. **Notes cannot be passed on the command line.** `hooks._BASH_CHARS` allows no quote, so `attempt check --change
   "..."` can never pass the hook (`hooks.py:143`, `:660-664`). Plan, notes and give-up text must be files the session
   writes with Write (allowlisted next to notes.md), and the verbs validate them. This matches D-05's "new verbs and
   files change together".
2. **New wrapper forms break two skill tests and three wrapper/hook tests immediately**
   (`test_skill.py:120`, `test_skill_readability.py:136`, `test_attempt_wrapper.py:1399,1625`,
   `test_hooks.py:585-586`). Since one plan owns watcom-decomp SKILL.md and goes last, the plans that add forms must
   change those tests to pin an explicit "forms the skill quotes" tuple, which the skill plan widens. Readability
   sessions should get no new form, and the plan and notes rule should apply to matching sessions only.
3. **The harness work is wider than "change an env var".** A Claude session pointed at a base URL without a non-empty
   `ANTHROPIC_AUTH_TOKEN` still sends the owner's claude.ai login to that URL. Codex has no default-deny command rule,
   and its `allow` rules run commands outside the sandbox. Antigravity keeps its permission rules only in the
   user-global `~/.gemini/antigravity-cli/settings.json`, and on AI Plus it gives Gemini 3.8 Flash only (Gemini 4
   Argon needs AI Pro or Ultra). Each non-Claude harness needs its own stream parser, init check, audit inputs and
   canary.

The two recorded runs (20261107-030004 and 20261107-170844) give the per-try rates for evidence item 9d:

| Run | Plain checks | Build failures (exit 2) | Mismatches (exit 1) | Matches (exit 0) |
|---|---|---|---|---|
| 030004 | 388 | 1 (0.26%) | 375 (96.6%) | 12 (3.1%) |
| 170844 | 665 | 1 (0.15%) | 653 (98.2%) | 11 (1.7%) |

FNV's figures for comparison are 42 / 55 / 3. Our build failures are almost nil, so the shared-header-gap ranking
(999.8) will have little data from these runs; causes must rank mismatch classes too.

**Primary recommendation:** order the driver-touching plans strictly (01 → 02 → 03 → 06 → 12 → 13 → 15 → 16), run the
independent plans (04, 05, 07, 08, 14) beside them, make every new session-written artifact a JSON file next to
notes.md validated by one function the wrapper and the driver audit share, and gate each non-Claude harness behind its
own canary before any arm runs.

### Locked Decisions

#### Plan and notes enforcement (999.6) and give-up records (999.5)
- **D-01:** `attempt check` hard-refuses (exit 2) when there is no plan, or when a check lacks change/why/expect
  notes. The message names exactly what is missing. A refused check does not use one of the 25 checks.
  — **Reversibility:** reversible
- **D-02:** The "observed" part of each check note is recorded automatically by the tool from the check result: exit,
  objdiff %, bytes differing, first_va, the window's first differing row and the region-board summary. The agent writes
  only change/why/expect, before each check. Nothing it records is self-reported.
- **D-03:** The plan (`attempt plan`) is required at every size and covers FRAME/SLOT/CALL/REGION.
  - Under 64 B, one REGION covering 0..size is enough.
  - At 256 B and up, REGION boundaries line up with the region board's 0x100-byte regions.
  - REGIONs must cover the whole function.
- **D-04:** `attempt giveup` takes these categories: `flags`, `block_layout`, `stack_layout`,
  `register_allocation`, `instruction_idiom`, `types_or_struct`, `call_convention`, `compile_error`, `other`.
  - They come from the 2026-11-07 survey's measured blockers. FNV's `eh` category does not apply to Watcom C.
  - The other fields are tried, still_differs and suspected_cause; best_code is the path of the best check.
  - D-23 still holds: no C text in records.
- **D-05:** New verbs and files change together:
  - `hooks.ATTEMPT_FORMS`;
  - `matching_write_allowed`, which the driver audit reuses;
  - `session.build_argv`'s allowedTools;
  - `tests/test_skill.py`'s pinned forms.

  The watcom-decomp skill learns giveup, plan, notes and the region board through superpowers:writing-skills, RED
  first. One plan owns SKILL.md in this phase.

#### Base-vs-head CI (999.11)
- **D-06:** Fork PRs are allowed, but every run is gated by a maintainer label (for example `match-check`). The
  workflow uses `pull_request_target` with main's own workflow and tools, and checks the PR out as data. No PR code runs
  before the compile.
- **D-07:** The compile runs inside the existing ReverseApoc Docker image on the owner's self-hosted runner, with
  Watcom mounted read-only, no orig/, and the network restricted.
- **D-08:** The compare: every src/ unit the PR touches is compiled at base and at head with the pinned cflags, and
  the object code (relocations included) must be identical. Comment-only and rename-only changes pass. Any byte change
  fails. New matches still go through the owner's gate.
- **D-09:** The workflow ships disabled: `workflow_dispatch` plus the label. `docs/ci.md` holds the runner setup and
  the security model. The owner registers the runner and turns it on. Agents never touch runner registration.
  — **Reversibility:** reversible

#### Name provenance markers (999.10)
- **D-14:** The form is `/* src: TAG 0xADDR (confidence: high|medium|low) */`, written C89-style beside the
  declaration. TAG is one of OPENAPOC, GHIDRA, UFOPAEDIA or GUESS. 0xADDR is the original function or data address
  that the name's evidence refers to.
- **D-15:** readlint rule RL07 requires a marker on every identifier that the readability pass renames from a
  placeholder (`func_`, `D_`, `param_`, `local_`), checked on the readability diff. A malformed marker is always an
  error. Already-matched units are not flagged until their next readability pass.
  - The watcom-readability skill learns the form through writing-skills, RED first.
  - A test proves the matched objects stay byte-identical, because markers are comments only.
  — **Reversibility:** costly — every later readability unit carries the form, so changing it means a rewrite pass
  over every named unit.

## Common Pitfalls

### Pitfall 1: free-text flags on the wrapper
**What goes wrong:** `attempt check --change "x"` is denied by the matching hook, so the session can never check.
**Why it happens:** `_BASH_CHARS` and exact-form matching (`hooks.py:143`, `:656-664`).
**How to avoid:** files next to notes.md plus fixed-form verbs.
**Warning signs:** the canary's check is "denied" in `permission_denials`.

### Pitfall 2: tests red between waves because of skill-quote assertions
**What goes wrong:** a plan adds a form, and `test_skill.py:120` and `test_skill_readability.py:136` fail until the
skill plan.
**How to avoid:** the form-adding plan changes those assertions to an explicit tuple of forms the skills quote today;
plan 09 widens it when SKILL.md learns the verbs. Keep readability-session forms unchanged.

### Pitfall 3: the canary breaks when enforcement turns on
**What goes wrong:** `CANARY_PROMPT` checks without a plan or note, so the check exits 2 and the canary FAILs.
**How to avoid:** the plan that adds enforcement updates `CANARY_PROMPT` and `_check_evidence`'s expectations in the
same commit.

### Pitfall 4: `flags.py` misreads schema 3
`flags.py:1395` treats only `== SCHEMA_V2` as v2. Fix it in plan 01 with a test.

### Pitfall 5: OAuth token sent to a third-party endpoint
**What goes wrong:** a base URL set with an empty or missing token sends the claude.ai login there.
**How to avoid:** refuse before any session unless the token is non-empty; test it with the env builder; the canary
proves the refusal (D-11, D-12).

### Pitfall 6: Codex `allow` rules escape the sandbox, and nothing denies by default
**How to avoid:** allow only the wrapper prefix; audit every `command_execution` and the attempt-dir inventory; the
wrapper ledger; the canary probes compound commands and identity.

### Pitfall 7: one attempt dir shared by two arms
**How to avoid:** per-arm run ids.

### Pitfall 8: stale-unit landings in `--land-held`
**How to avoid:** the unit and include/ must be unchanged since `view_head`, else skip and report.

### Pitfall 9: the gzw cache serves a stale pack
**How to avoid:** add the give-up and best-C inputs to gzw's context cache key (gzw ruling: "the key holds exactly the
inputs each output READS").

### Pitfall 10: "held" naming collision
The asm hold already uses `held` in code and console text (see Anti-patterns).

### Pitfall 11: Windows Codex sandbox surprises
Elevated or unelevated failures, slow `apply_patch` (13-20 s per patch reported) and `unified_exec` running as the real
user. Budget the 30-minute wall clock accordingly, and check the identity in the canary.

### Pitfall 12: two plans editing watcom-readability SKILL.md in parallel (07 and 14)
They must run one after the other.

### Pitfall 13: `test_workflows.py:127` pins the workflow list
Plan 08 must update it.

### Known threat patterns
| Pattern | STRIDE | Mitigation |
|---|---|---|
| Shell injection through wrapper arguments | Tampering, Elevation | Keep `_BASH_CHARS`; files instead of text arguments |
| OAuth token leak to a third-party base URL | Information disclosure | Non-empty token required; the canary proves refusal |
| Disassembly sent to an unintended backend through a typo | Information disclosure | `--night-model` plus `--allow-egress` both required (D-11) |
| Codex allow rule used as a sandbox escape | Elevation | Allow only the wrapper prefix; audit commands; canary compound-command probe |
| Forged checks.jsonl by a sandboxed agent | Tampering | Gate-only MATCHED; wrapper hash ledger outside the workspace |
| Fork PR code execution on the self-hosted runner | Elevation | pull_request_target with main's tools, PR as data, label plus variable gate, network none, read-only mounts, no secrets |
| Game bytes in committed records | Information disclosure (legal) | `_LONG_HEX`, `_TEXT_CAP`, no window in records |
