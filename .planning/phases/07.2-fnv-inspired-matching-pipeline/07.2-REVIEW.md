## Summary

This review covered the schema-3 ledger, give-ups, plan and notes, the region board, `causes`,
RL07, the slot-model lifter fix, `compare-objects` and the match workflow, and the drive harness:
night-model, picks, hold, land-held, hosted backends, the Codex and agy adapters, and multi-arm.
The Claude-harness hook paths and the token-leak guard hold up. Every arm of a multi-arm night
goes through `refuse_arms` (preflight per arm, `refuse_stray_egress`, `max_workers`),
`refuse_unproven` and `_audit`. The record writers match `RECORD_FIELDS_V3`.

Most of what is left is in the signed-in harnesses (Codex, agy). The prevention there rests on
two things a session can reach: its cwd is its writable workspace, and the one allowed command
prefix (`uv run --frozen reverseapoc attempt`) resolves its project from that cwd. The
after-the-fact audits also pass anything they do not recognize instead of failing closed.
Secondary concerns:
- the egress gate trusts a self-declared config flag;
- `--land-held` silently cannot land two held functions of one unit;
- the match workflow passes agent-instruction Markdown and symbols.csv-only changes with nothing
  compared.

Real Codex/agy CLI behaviour (event field names, whether rules reload, how commands are wrapped)
is not reported as a defect here. Each finding below is about the driver's own code and its own
stated model of those CLIs.

## Critical Issues

### CR-01: A Codex session can redirect the one allowed command, `uv run --frozen reverseapoc attempt`, to code it wrote itself

**File:** `tools/reverseapoc/session.py:147-162`, `tools/reverseapoc/driver.py:1311-1331`, `tools/reverseapoc/driver.py:3600-3607`
**Issue:**
- A Codex session runs with `--cd <attempt dir>` and `--sandbox workspace-write`, so it may
  create any file in its attempt dir. That directory is also the cwd of every command it runs.
- The generated rule allows any argv that starts with `uv run --frozen reverseapoc attempt`. The
  driver's own model of Codex (driver.py:1302) is that "its `allow` rules run outside the
  sandbox".
- `uv run` finds its project by walking up from the cwd. A session can write a `pyproject.toml`
  and a `uv.lock` (plus a local path package) into the attempt dir with file_change. The next
  allowed `uv run --frozen reverseapoc attempt check` then resolves `reverseapoc` from that
  project, so session-written code runs outside the sandbox, with the network on and as the
  owner's user.
- The post-session audit does flag the planted files (`codex_write_strays`,
  `codex_inventory_strays`). By then the code has already run. It can have read orig/ and sent
  it anywhere (D-10), or written outside the checkout (the user profile, another tool's config),
  which no audit looks at. The command itself passes `codex_command_strays`, because it is an
  exact wrapper form.
- Even if allowed commands do stay sandboxed, the same trick runs arbitrary code inside the
  sandbox. Its output (orig/ bytes, for example) then reaches OpenAI through the command result,
  under a command the audit accepts.
- hooks.py's own hook command already pins `--project "$CLAUDE_PROJECT_DIR"` for this reason.
  The wrapper prefix does not. agy has the same shape (its cwd is also the attempt dir) and is
  protected only by its `write_file` allowlist, which the canary has not yet proven.

**Fix:** Do not let uv discover the project from a directory the session can write.
- Set `UV_PROJECT=<repo root>` (or `UV_PROJECT_ENVIRONMENT` plus `UV_NO_CONFIG=1`) in
  `_Claim.env` for every signed-in session.
- Make the Codex rule name the absolute venv entry point (`<repo>/.venv/Scripts/reverseapoc`)
  instead of the `uv run` prefix.
- Add a canary probe that plants a `pyproject.toml` in the attempt dir and checks the wrapper
  still runs the repo's tool.

```python
# driver.py, _Claim.env, for signed-in sessions
if self.signed_in:
    own[attempt.WRAPPER_LEDGER_ENV] = str(self.wrapper_ledger)
    own["UV_PROJECT"] = str(self.repo)      # never discovered from the session's cwd
    own["UV_NO_CONFIG"] = "1"               # no uv.toml from the workspace
```

## Warnings

### WR-01: The egress gate trusts the self-declared `sends_disassembly` flag

**File:** `tools/reverseapoc/backends.py:114-117`, `tools/reverseapoc/backends.py:215-233`
**Issue:**
- `Arm.egress` is `sends_disassembly and backend != ANTHROPIC`.
- `load_arms` accepts `sends_disassembly = false` on any arm: a Codex or agy arm (whose CLI
  always sends the prompt to OpenAI or Google), or a claude-harness arm with an `https://`
  non-loopback `base_url`.
- Such an arm then runs with `--night-model X` alone. `preflight` asks for no `--allow-egress`,
  and `cli._harness_conflict` even refuses one. So one wrong boolean in backends.toml sends packs
  to a new endpoint, which D-11 says a typo must never do.

**Fix:** In `_arm`, refuse `sends_disassembly = false` unless `harness == "claude"` and
`base_url` is loopback (or the arm is the Anthropic login). Pin this with a test.

### WR-02: The agy audit passes any tool step it does not recognize

**File:** `tools/reverseapoc/agyjson.py:54`, `:166-181`, `:146-163`, `:230-241`; `tools/reverseapoc/driver.py:1403-1419`
**Issue:**
- `_steps` drops every `step_update` whose `tool_name` is not a string (line 172), so such a
  step's command never reaches `commands()`.
- `_paths` drops a step that has neither `command` nor one of `_PATH_KEYS` (line 236-238), for
  example a URL fetch, a directory listing or a search tool.
- A step counts as a write only when its tool name matches `_WRITE_TOOL`. An unrecognized
  writing tool is audited as a read. `read_strays` passes any read inside the checkout, including
  other workers' gitignored attempt dirs, which git status never sees.
- Denials are paired with steps by (action, target) count only, never by step state or order. A
  denial that has no step of its own can use up the count of a step with the same target that did
  run.

Each of these is fail-open, while the docstring of `_signed_in_strays` promises fail-closed.

**Fix:**
- Treat a tool step whose name is missing, or whose shape is neither a command nor a known path
  key, as a stray.
- Classify reads by an explicit allowlist of read-only tool names; anything else that has a path
  is a write.
- Drop a step as denied only when the step itself records a denied state.

### WR-03: The Codex audit ignores every item type except `command_execution` and `file_change`

**File:** `tools/reverseapoc/codexjson.py:79-147`, `tools/reverseapoc/driver.py:3765-3766`
**Issue:** `_signed_in_strays` reads only `codexjson.commands` and `codexjson.write_targets`. An
`mcp_tool_call`, a `web_search` or any other item a Codex session produces passes the audit
silently. The same fail-open shape as WR-02.

**Fix:** Add a `codexjson.unknown_items(events)` that returns every item type outside a known
harmless set (`agent_message`, `reasoning`, `todo_list`, `command_execution`, `file_change`), and
make each one a stray with `_AUDIT_MARK`.

### WR-04: The attempt-dir inventory accepts session files and the transcript by name, links included

**File:** `tools/reverseapoc/driver.py:1564-1574`
**Issue:**
- `_inventory_problem` returns None for `transcript.jsonl` and any `_SESSION_FILES` name before
  it looks at the digest. A `notes.md`, `plan.json` or `giveup.json` that `attempt_inventory`
  recorded as `link:<target>` therefore passes. This breaks the "a link by its target, never
  followed" contract.
- `_giveup` then reads `giveup.json` through the link (`read_giveup` follows it), and so does
  the wrapper with `plan.json` and `check-note.json`.

**Fix:** In `_inventory_problem`, flag any digest that starts with `link:` (or `outside:`)
before the name allowlist applies:

```python
if digest.startswith(("link:", "outside:")):
    return "a link or a path outside the attempt dir"
```

### WR-05: The Codex rules file lives in the session's writable workspace

**File:** `tools/reverseapoc/driver.py:1311-1331`, `tools/reverseapoc/driver.py:3739-3745`
**Issue:**
- `<attempt dir>/.codex/rules/attempt.rules` is inside the workspace-write root. A session can
  apply_patch in its own `prefix_rule(..., decision="allow")`. If Codex reads rules again during
  the session, those commands run under the same unsandboxed allow path as CR-01.
- The audit only notices afterwards (the launch inventory). agy's settings file was deliberately
  put outside its workspace; this one was not.

**Fix:** Mark the rules file and `.codex/` read-only after writing them (`os.chmod(..., 0o444)`
or the Windows read-only attribute). Add a canary probe that tries to edit the rules file and
then runs a command that only the edited rule would allow.

### WR-06: `--land-held` lands at most one held function per unit; the others are always refused as stale

**File:** `tools/reverseapoc/driver.py:4711-4777`
**Issue:**
- `land_held` sorts the landings by (exe, unit, start) "so same-unit landings report one after
  the other".
- `_land_one` lands the hold attempt's whole unit file (`checks/NNNN.c`) and commits it. For the
  next held function of the same unit, `_stale_reason` runs
  `git diff --quiet <view head> HEAD -- <unit>`. The unit has just changed, so it returns 1 and
  the landing is REFUSED with `LAND_HELD_STALE`.
- Every hold-exact function after the first one in a unit is lost until a new hold run. A
  stratified spike can easily pick two rows of one unit.

**Fix:** Either refuse such pairs up front with a clear reason, or land the second function by
splicing only its definition onto the current unit (the gate still proves it). At minimum,
change the docstring and the console line to say that only one function per unit lands in each
`--land-held` run.

### WR-07: The match workflow passes agent-instruction Markdown and symbols.csv-only changes with nothing compared

**File:** `.github/workflows/match.yml:84-95`, `:116-139`
**Issue:**
- `*.md) continue` accepts any Markdown path, including `CLAUDE.md`, `.claude/rules/*.md` and
  `.claude/skills/*/SKILL.md`. Those files are inlined into every drive session's prompt
  (`codex_prompt` reads SKILL.md), so they steer the agents.
- A PR that changes only `config/<exe>/symbols.csv` (or only Markdown) produces an empty
  units.txt, and the job exits 0 having compared nothing.
- A symbols.csv change that remaps a name used by an untouched unit is never checked against that
  unit, because only touched units are compiled.

A green result therefore says more than the job proved.

**Fix:**
- Refuse `.claude/**`, `CLAUDE.md`, `.planning/**` and `.github/**` paths, which need the owner.
- Fail (or label as needing the owner) a symbols.csv change that comes with no touched unit.
- Or compile every unit that names a changed symbols.csv row.

### WR-08: A writable, shared venv volume is mounted into the container that compiles PR-controlled C, and actions are not pinned

**File:** `.github/workflows/match.yml:50`, `:58`, `:122-129`
**Issue:**
- Every `image` call mounts the persistent named volume `reverseapoc-match-venv` read-write at
  `/opt/venv`, including the call that compiles the PR's C with a 1990s compiler.
- Anything that gains execution in that container (a compiler bug fed hostile input) can plant a
  `.pth` or patch `reverseapoc` in the volume. Every later run, including later
  `compare-objects` verdicts, would then execute it, and a poisoned compare could always print
  "same".
- `actions/checkout@v7` is a mutable tag, used on a self-hosted runner under
  `pull_request_target`.

**Fix:**
- Mount the venv volume `:ro` for the compile and compare steps; populate it in a separate
  step, or use a fresh per-run volume.
- Pin both checkouts to a full commit SHA.

### WR-09: Claude-harness sessions strip a fixed list of variables, so other credential and routing variables reach hosted endpoints

**File:** `tools/reverseapoc/backends.py:69`, `tools/reverseapoc/backends.py:285-299`
**Issue:**
- For a claude-harness arm, `session_env` removes only `INHERITED`: the base URL, the auth token,
  the three model pins and `EGRESS_ENV`.
- `ANTHROPIC_CUSTOM_HEADERS`, `ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`,
  `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`/`CLAUDE_CODE_USE_VERTEX` with their base
  URLs, and every OpenAI or Google key are inherited.
- On a hosted arm, `ANTHROPIC_CUSTOM_HEADERS` is sent to the third-party endpoint with every
  request. `CLAUDE_CODE_USE_BEDROCK=1` reroutes the session away from the configured base URL
  entirely.
- Codex and agy sessions get the full `ANTHROPIC_*` strip; Claude-harness sessions do not.

**Fix:** For claude-harness arms, strip every `ANTHROPIC_*` and `CLAUDE_CODE_USE_*` name, plus
OPENAI_ENV and the Google keys (as `_foreign` already does for signed-in arms), before adding back
the arm's own endpoint, token and pins.

### WR-10: The Codex and agy prompt contradicts itself on how to read files

**File:** `tools/reverseapoc/session.py:191-204`, `.claude/skills/watcom-decomp/SKILL.md:18`
**Issue:**
- `codex_prompt` inlines the watcom-decomp skill body. That body says "The only Bash: the seven
  wrapper commands ... Look around with Read, Grep and Glob."
- Codex has no Read, Grep or Glob tools, and the closing block says "run nothing else, not even
  to read or list a file".
- A Codex session that follows the skill and reads its unit or a checks/NNNN.json runs a shell
  command. `codex_command_strays` flags it, and the whole night stops on GUARDRAIL.

**Fix:** For signed-in harnesses, state the harness's own read path in the closing block (the
pack that `attempt context` prints, and what `attempt check` prints). Add a sentence there that
overrides the skill's Read/Grep/Glob line, or strip that row from the skill body when building
the prompt.

### WR-11: RL07 never asks for a marker on a rename whose declaration is in a header

**File:** `tools/reverseapoc/readlint.py:983-997` (`_rl07_renames`), `tools/reverseapoc/readlint.py:1224-1246` (`unmarked_declarations`)
**Issue:**
- RL07 judges renames only against declarations in the unit; headers get only `_rl07_form`.
- `unmarked_declarations` says outright that "a name the unit only uses ... needs none".
- A `D_` global declared `extern` in an include/ header, renamed through a proposal, therefore
  lands with no provenance marker anywhere, despite D-15: "every identifier that the readability
  pass renames from a placeholder".

**Fix:** When a proposal renames a name the unit only references, require the marker on its
declaration in the header that declares it: `_Run.closure` already lists the headers. Or refuse
such a proposal until the header carries the marker.
