# Phase 07.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Source: 07.2-RESEARCH.md § Validation
> Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest via uv, plus ruff |
| **Config file** | `pyproject.toml`, `tests/conftest.py` |
| **Quick run command** | `uv run pytest -q tests/<file>.py -x` (per task; files below) |
| **Full suite command** | `uv run pytest -q && uv run ruff check .` on the host, then `docker compose run --rm test`, **one after the other, never at the same time** |
| **Estimated runtime** | quick about 10-180 s; full host suite about 14-17 min; container similar |

Pytest `--basetemp` must sit **outside `build/`**, because the hooks refuse paths containing `build` (batch 261109-gzs
lesson). Use a per-run folder in the scratchpad or system temp.

---

## Sampling Rate

- **After every task commit:** run the task's quick command(s) below.
- **After every plan:** full host suite and ruff, then the container suite.
- **Before `/gsd-verify-work`:** the plan 07.2-11 gate, on the main checkout:
  - host suite, then container suite;
  - `gate --all` and `ninja verify` exit 0;
  - `drive --canary` PASS;
  - `drive --dry-run --picks` works.
- **Max feedback latency:** about 180 s for the per-task quick runs.
