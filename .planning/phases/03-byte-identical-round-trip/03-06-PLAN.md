- WR-06, corrected mechanism (sources: the ninja manual, ninja src/util.cc, ninja src/lexer.in.cc):
  - ninja shell-quotes `$in` and `$out` when it expands them in a command. On POSIX it single-quotes any path
    holding characters outside [A-Za-z0-9_+,-./]. On Windows it double-quotes only where needed, and runs
    the command through CreateProcess, with no shell. So the review's suggested `"$in"` would double-quote:
    `parse-le $in` stays unquoted.
  - configure.py's ninja_path (:52-54) escapes only `$`, space and `:`, and find_executables (:57-62)
    accepts any *.exe name. ninja 1.11.1, the container's version (docker/Dockerfile:91), has no escape for
    `|`, LF or CR in a build path. `orig/a|b.exe` becomes input `orig/a` plus implicit dependency `b.exe`,
    and an LF or CR breaks the whole file.
  - Literal text in a rule command is not quoted by ninja. So the `--orig DIR` that WR-05 writes goes
    unquoted to /bin/sh in the container and to CreateProcess argv splitting on Windows. POSIX single
    quotes are not quotes for Windows argv, and sh still expands `$` and backticks inside double quotes. A
    path is portable only if it needs no quoting at all. shlex.quote alone is POSIX-only.
