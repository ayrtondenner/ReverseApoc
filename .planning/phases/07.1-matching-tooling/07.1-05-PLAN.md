<objective>
Upgrade what `attempt asm` shows: jump-table case targets, and the register value at each call, terminal only (D-05).

Purpose: spike 011's agents asked for exactly these two views. `asm.listing` prints `dd` items only when a table sits inside the
row, and tables usually sit in a data-in-code row before the function, so an agent reading an indirect jump sees no targets. An
agent also cannot see which earlier value a register holds at a call, though the converter already knows it.

Output: `asm.case_notes`, `asm.annotated`, `lift.call_notes`, an upgraded `attempt.cmd_asm`, and curve point 5.

**The choice this plan pins: annotate the text, do not re-render it.** `cmd_asm` keeps reading the listing through `listing_text`
and lays the notes onto that text in memory, matching each `  0x<va>  ` line. Rendering a fresh listing in `cmd_asm` would drop the
"no listing yet" path and its tests. Annotating leaves `asm.listing`, `write_listings` and those tests as they are, so an
unannotated row prints exactly what it printed before.
