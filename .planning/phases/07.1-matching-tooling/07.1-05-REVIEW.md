## Summary

The review covers the diff from `811be291` to HEAD: `asm.case_notes`, `asm.annotated`, `lift.call_notes`, `Block_.note_values` and `attempt.cmd_asm`.

**Case notes hold up.** A read-only sweep of both EXEs found 177 tables, every one with a note. No table ran into a table that another row jumps through. I have no correctness finding against `case_notes` or `annotated`.

**Call notes do not meet the plan's bar.** The plan's truth is "the value each argument register holds at a call", and the SUMMARY says each deviation keeps a note true. The liveness filter removes stale text, but it does not cover three other ways a note goes wrong. Some notes name the wrong stack slot (CR-01), some print a low part as the whole register (WR-01), and some use a variable name that differs from the register of the same name (WR-02). The `call_notes` docstring also claims the census cannot change a value, and that is false (WR-03).

These faults come from lifter state that only needed to be good enough for a draft, and a draft is proven by compiling it. A note gets no such check, so the agent takes it as fact. A wrong note cannot produce a false match, because bytes still decide. It can only send a session down the wrong path.

**How the numbers were measured.** One-off scripts in the session scratchpad read `orig/` and wrote nothing under the repository. They ran `call_notes`' logic over all 3616 code rows, which gave 17158 notes, the same total as the SUMMARY's 9651 + 7507. The sweep shared one signature dict per EXE, as the SUMMARY's did. The machine's `esp` came from a separate forward pass over the lifter's blocks.

**YAGNI:** no break found. The diff adds no unrequested option, flag or single-implementation abstraction, and no code for later. The guards beyond the plan are boundary validation that `.claude/rules/tools.md` keeps: the bent-table checks and the data-in-code early return.

## Critical Issues

### CR-01: Call notes name the wrong stack slot once the lifter's esp drifts from the machine's

**File:** `tools/reverseapoc/lift.py:682`, `:1004-1013`, `:1131-1137`, `:288-291`, `:1383-1389`
**Issue:** `Block_.slot` names a local from `self.esp + disp`, and `self.esp` is wrong in three cases:

1. **Every block starts at `lf.esp0` (L682).** A value pushed before a branch is forgotten at the block edge. Watcom's inline string copy does exactly this: a `push edi`, a loop, then a `pop edi`.
2. **`hole()` never moves `esp`.** A push, a pop, a mid-body `sub esp, N` or a call whose callee pops arguments can become a hole. The instruction's stack effect is then lost for the rest of the block. A mid-body `sub esp, N` is always a hole, because `arith` reads `esp` as a register.
3. **`signature` reads `nstack` from the row's last instruction only (L288-291).** A row that ends in a bare `ret` but returns through `ret 10h` elsewhere reads as taking no stack arguments, so the caller's `esp` stays low after the call.

These cases were harmless while a hole meant "this draft can never be exact". `note_values` now prints the result as a value.

Reproduced on hand-written bytes, with a callee that takes two registers:

- `sub esp,10h; mov [esp+8],ecx; push ecx; test ecx,ecx; je +1; nop; L: mov edx,[esp+0Ch]; call f` gives `edx=s_4`. There is no hole in this row. The machine reads the slot written as `s_8`, and nothing ever wrote `s_4`.
- `sub esp,10h; mov [esp+8],ecx; push esi; mov edx,[esp+0Ch]; call f`, with `push esi` a hole, also gives `edx=s_4`.

Real rows, with the first drift classified:

| | UFO2P | TACP |
|---|---|---|
| Rows with an `esp` operand read at the wrong offset | 57 | 43 |
| `esp` operands misnamed | 342 | 282 |
| Notes naming a slot one of those operands misnamed (upper bound, matched by name) | 88 | 42 |
| First drift at a block edge | 16 | 11 |
| First drift after a hole on a call, `sub` or `push` | 32 | 21 |
| First drift after a call the lifter treats as popping the wrong amount | 9 | 11 |

UFO2P `0x19400` and `0x57A80` show the block-edge case with `esp` off by 4. No test covers a note that reads a stack slot after any of these.

**Fix:** Stop printing slot text the lifter cannot vouch for. The smallest change has two parts:

```python
# Block_.hole: a stack effect the run did not apply makes every later slot name a guess
if any(ci.reg_name(r) == "esp" for r in ci.regs_access()[1]):
    self.esp_lost = True

# Block_.note_values: leave out text that reads a slot named after the esp was lost
known = [r for r in ARG_REGS if r in self.regs and r in self.needed
         and not (self.esp_lost and _STACK_NAME.search(self.regs[r].text))]
```

`_STACK_NAME` matches `s_<hex>` and `r_p<n>`. `esp_lost` must also be set at the start of a block entered with `esp` other than `esp0`, which needs each block's entry `esp` from a forward pass in `Lifter`. Take `nstack` from any `ret N` in the row, not only the last. That last change moves lifter output, so it needs curve point 5 re-measured.

## Warnings

### WR-01: A byte or word write prints as the whole register's value

**File:** `tools/reverseapoc/lift.py:711-713`, `:1388-1389`
**Issue:** `Block_.set` replaces the full register's expression with the low part's text and only records `size`. `note_values` then prints that text under the 32-bit name.

`mov eax, 1234h; mov al, 5; call f` gives `eax=5`, while the machine holds `0x1205`. `mov dx, [eax]` gives `edx=*(unsigned short *)((char *)r_eax)` with the upper half of `edx` still live.

176 real notes (98 UFO2P, 78 TACP) hold such a register, leaving out writes over a known zero. Examples are UFO2P `0x100B7` and TACP `0x12FFD`. The count is a floor, because it only sees writes in the same block as the call.

The low part is often the argument a `char` or `short` parameter reads, so this is usually a naming fault. The note still states a false 32-bit value.

**Fix:** Print the width that was written, as `al=5` or `dx=...`. `E.size` alone also marks `movzx` results, whose text is exact. So either record the partial write in `Block_.set`, or accept `al=` for those too, which stays true.

### WR-02: A note's `r_<reg>` reads as the register but means the draft's variable

**File:** `tools/reverseapoc/lift.py:1383-1389`
**Issue:** `mov edx, eax; mov eax, 5; call f` gives `eax=5 edx=r_eax`. In the draft that is correct, because `r_eax` is a variable that has not changed. `attempt asm` prints no draft, though, and the `watcom-decomp` session never sees that variable. The note reads as `edx` holding `eax`, which it says is 5.

1357 of 17158 real notes (7.9%) put `r_X` in one register's value while the same note gives `X` a different value. Examples are UFO2P `0x103F5` and TACP `0x104C8`. `docs/toolchain.md` describes `<expr>` and `h_<address>` but never says what `r_` means. `test_call_notes_show_the_argument_registers` pins the spelling without settling this.

**Fix:** Say what the name is, in the one bullet of `docs/toolchain.md` and in plan 6's `SKILL.md` update: `r_<reg>` is the value that register held at the last point the converter named it, not the register now. Better, print the note so the two cannot be confused, for example with a distinct `in_ebx` spelling for a value from entry or a merge.

### WR-03: The claim that the census decides no value is false, and a good cache is ignored

**File:** `tools/reverseapoc/lift.py:1731-1745` (docstring at L1735)
**Issue:** The docstring says "the census only decides `void`, so no value here depends on it". The plan said the same, but the plan guarded only an absent cache. Deviation 5 widened that to always, so a valid `build/lift/result-used-<exe>.json` is never read either.

Without the census, `signature` keeps `returns` true for a void callee, and its "returns an argument unchanged" branch (L303-306) can then add `eax` as a parameter. That liveness runs back through the caller and changes the notes.

Running the sweep with the existing cache loaded changes 103 notes in 70 rows:

- 20 notes exist only without the census, and none exist only with it.
- UFO2P `0x10F46` shows `eax=r_eax` as an argument the census says is not one.
- TACP `0x11A3D` loses a real value: `eax=(short)r_edx` with the census, the bare name `eax=r_eax` without. That is the "only named" text `note_values` exists to drop.
- UFO2P `0x326D6` prints `r_ebx` where the census run prints `r_eax`.

No test compares the two runs.

**Fix:** Keep the rule that a session never builds the census, and let it read one that exists. Split the file read out of `result_used`, and have `call_notes` hold `_BUILDING` only when that read finds no valid file. `test_call_notes_never_build_the_census[truncated]` stays green, because a truncated file reads as none. Add a test that a valid cache reaches the notes. If the census stays unread on purpose, correct the docstring and the SUMMARY's key decision instead.

### IN-02: Two table readers with different rules

**File:** `tools/reverseapoc/asm.py:280-287`, `tools/reverseapoc/lift.py:378-385`
**Issue:** `asm._table_targets` and `Lifter.table_cases` both read a table from fixups, and each repeats the rule "a table runs to the next table or the holder's end". They already differ: `asm` requires `SRC_OFF32`, while `lift` accepts any 4-byte field, rel32 included. The SUMMARY found equal case counts on the real tables, but it did not compare the targets.
**Fix:** `lift.py` already imports from `asm.py`, so have `table_cases` call one shared reader there. That moves `lift.py` code, so pin it with the existing switch tests first.

### IN-03: No test feeds a real listing to `annotated`

**File:** `tools/reverseapoc/asm.py:54`, `tests/test_asm.py:410-424`, `tests/test_attempt_wrapper.py:961-967`
**Issue:** `_LISTED_ADDRESS` repeats `_line`'s format, and `annotated` drops a note with no matching line by design. Every test uses hand-typed listing text. If `_line` changed, all notes would silently vanish with the suite still green.
**Fix:** Add one test that runs `asm.annotated(listing(row, ...), {va: "x"})` on a row from `_inputs` and asserts the note lands on that line.

### IN-04: Two untested or unbounded corners of the note text

**File:** `tools/reverseapoc/asm.py:311`, `tools/reverseapoc/lift.py:1747`
**Issue:**
- `target_name(..., code=True)` for a case target in no row has no test. The SUMMARY's deviation 7 says so ("by reading only"), although that is the branch which replaced a wrong `D_` name.
- Notes have no length limit and are joined by a plain space inside expressions that also hold spaces. 312 real notes pass 200 characters, and the longest is 1005 (UFO2P `0x7156D`).

**Fix:** Add a table entry pointing into no row to `_table_fixups`, and assert the bare address. Join the registers with `, ` or another separator no expression holds. A length limit is the owner's call.


### IN-05: Draft text depended on the string hash

**File:** `tools/reverseapoc/lift.py`
