<objective>
Build the failure classifier (register, slot, branch, tail, size) that routes each function to the converter, the search or an
agent (D-04).

Decisions covered: D-04, D-07, D-08, D-10, D-11, D-13, D-14, D-15, D-16, D-17, D-18, D-19, D-20, D-21, D-22, D-23, D-27, D-28.

Purpose: the phase's final report must say how many rows go to agents, and each tool only pays where its failure lives. A
first-difference `key` cannot say that: on drafts the first differences cluster in the prologue (`sub esp, N | sub esp, N`, 45
rows), so it reads "frame or save set" for most rows. Comparing tokens under progressively wider masks does say it.

Output: `tools/reverseapoc/classify.py`, batch records with `class` and `route`, a routing summary, and curve point 4.

**Choices this plan pins.**
- *Classification runs at batch time, inside `reverseapoc batch`.* A class needs both byte strings, and records hold none, so
  `_file_records` classifies while the object is on disk. `cli.py` imports both `batch` and `classify`, so there is no import
  cycle, and no re-judging: `batch.judge` does not change.
- *There is no new verb.* `reverseapoc batch` is how the owner already runs this over a directory of drafts, and its records are
  the report. D-04 asks for routing, not a verb.
- *A sixth label, `mixed`, exists for honesty.* D-04 names five classes, and a row can fit none of them. It routes to an agent.
- *The route order is a hole first, then exact, then class slot, then the research's table.* A draft holding a hole can never be
  exact and plan 3 never searches one, so it routes to an agent; `_file_records` already holds the source, so the signal costs one
  keyword. The table sends `exact`, `near` and refused rows to the converter, slot rows to the search and the rest to an agent.
  Checking slot before `near` sends a near-miss whose only difference is stack offsets to the search, which is the tool for it.
