<domain>
## Phase Boundary

This phase builds the deterministic tooling that moves Tier 1 matching past what agents reach alone.
Spike projections put functions of 256 B and up (about 445 of them) on the critical path, and agents
fail there on stack slots, registers and types. The target is about 6-8 weeks to Tier 1 matched.

Six plans, in order: `reverseapoc search`, the stack-slot model, converter v1, the failure classifier,
disassembly view upgrades, and the watcom-decomp skill. A measurement gate follows each plan.

The start gate is met: 07-48, 07-48b and 07-48c are merged with CI green, and flag proposals F-0045 to
F-0057 are landed or held. Phase 7 itself stays open: its close gate 07-41 needs this phase's tools.

</domain>

<decisions>
## Implementation Decisions

### The six plans, in this order
- **D-01:** Plan 1 is `reverseapoc search EXE ADDR FILE`: a declaration-order, scope and type permutation search. About 600 compiles per function, through `batch.compile_batch`. The score masks stack offsets first, and the tool reports the slot map.
- **D-02:** Plan 2 is a wcc386 10.6 stack-slot model for `-4r -s` and `-4r -oneatx -s`, calibrated on our clean-room `probe/` only.
- **D-03:** Plan 3 is converter v1: spike 010's `lift.py` moved to `tools/`, plus holes, ah/dh bytes, switch tables, stack structs, setcc/sbb, x87, a short hint and an idiom check. It fixes the KeyError on jumps to filler.
- **D-04:** Plan 4 is a failure classifier (register/slot/branch/tail/size) that routes each function to the converter, the search or an agent.
- **D-05:** Plan 5 is the disassembly view upgrades: jump-table case targets, and the register value at each call, terminal only.
- **D-06:** Plan 6 updates the watcom-decomp skill through superpowers' `writing-skills`. It is `autonomous: false`, and its first task is the owner checkpoint that shows the curve.
- **D-07:** The six plans are sequential: each depends on the one before it. New code goes in `tools/reverseapoc/` beside `batch.py`. Extend batch and judge, never fork them.

### Measurement gate
- **D-08:** After every plan, run the converter over all of Tier 1 (exact count per bucket) plus a fixed, seeded 64 B+ sample with the seed and rows committed. Record both in the SUMMARY and in `07.1-CURVE.md` in the phase directory.
- **D-09:** Plan 1 opens by recording curve point 0, so movement has a base.
- **D-10:** A tool that moves neither number is not polished. Stop the phase after two plans in a row that move nothing; every plan's closing task checks this.

### Rules for the whole phase
- **D-11:** No matching nights while 7.1 code is being written or tested.
- **D-12:** Search matches use the trailer `Matched-By: reverseapoc search`.
- **D-13:** Reused code from brotchie/daggerfall-decomp or abdulahmad/NHL95PC is allowed, and reuse is the default. Each copied or adapted file keeps a header naming its origin repo and path, as `check.py` does for Theme Hospital and `relocs.py` for KKND, with a row in `docs/tools.md` and a line in `docs/legal.md` and the README's credits. Their code is read through a scratch clone and never run. Subagents have no network, so the main session fetches it into a fresh scratch directory for them.
- **D-14:** Plans run on the main checkout by the recipe: a `<precondition>` that `git-dir == git-common-dir`, the temporary `git.allow_default_branch_commits`, `dispatch-isolation --force-isolation none`, and a sequential prompt with a bound `<project_root_pin>`. The host and container suites never run at the same time.
- **D-15:** Dispatched agents never push and never use the network.

### Item A: YAGNI is applied, as tasks or verification steps in every plan
- **D-16:** Each plan's `read_first` lists `.claude/rules/tools.md` (its "YAGNI: scope, not effort" section) and `docs/ceremonies.md`.
- **D-17:** Tasks build only what the plan asks for, and each SUMMARY has a one-line-per-item "Seen, not built" list.
- **D-18:** Each plan has a code-review task that records YAGNI breaks as `IN-` findings: an unrequested option or flag, a single-implementation abstraction, or code written for later. Otherwise the review prompt is unchanged: YAGNI never makes a review shorter.
- **D-19:** YAGNI never applies to C or headers (`.claude/rules/src.md`). C produced by the 7.1 tools lands only through the gate, as match commits.
- **D-20:** A tooling commit changes nothing under `src/` or `include/`. Each plan has a verification step that runs `git diff --stat <commit>^ <commit> -- src include` for every tooling commit and expects it empty.

### Item B: measure whether it pays off, in every plan
- **D-21:** The decision rule is `07.1-YAGNI-MEASURE.md` in the phase directory, written before planning and never edited.
- **D-22:** Each plan's closing task records its row in `07.1-YAGNI-RESULTS.md`: `L`, `T`, `M`, `E`, `US$`, findings by severity, `Y`, `D` so far and `C`, using `measure_train.py`.
- **D-23:** `must_haves.truths` in each PLAN frontmatter is the measure's `M`, so it is stated honestly and not padded.
- **D-24:** After plan 2, the closing task computes the verdict from the rule and reports it. An INCONCLUSIVE verdict proposes the paired spike and does not run it.

### Item C: the rule reaches the subagents
- **D-25:** Plan 1's verification includes a transcript check of whether `gsd-executor` and `gsd-code-reviewer` received the YAGNI section, and how: the path-scoped rule load after a read under `tools/`, `tests/` or `configure.py`, an explicit read, the CLAUDE.md pointer only, or not at all. If either missed it, it is reported. GSD's installed agent files are never edited.

### Claude's Discretion
- Internal module layout, function names and data shapes inside `tools/reverseapoc/`, within the rules above and `.claude/rules/tools.md`.
- The sample's seed value and size, and the exact bucket names, provided the seed and rows are committed and the buckets are the converter's real outcomes.
- How the plans split into tasks, and which task is the tracer.
