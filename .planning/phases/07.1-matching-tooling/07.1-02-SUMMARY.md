## What the probe measured against M1 to M5

This is the main result. Every rule below comes from `probe/cg_slots.c` or scratch clean-room C; no matched row is an input. The two cells agree on every memory shape.

| Rule | RESEARCH's preview | Measured |
|---|---|---|
| M1 size order | largest lowest | **Holds**, in every shape, ties or not |
| M3 padding | sizes pad to 4 | **Holds**, and nothing aligns past 4: a `double` sits at 0xC. New: a local nothing uses takes no slot |
| M2 ties | first declared highest | **Much narrower.** True only when the whole frame has one size, of 1, 2 or 4 bytes |
| M4 scope | scope changes the order | **Narrower, and the key differs.** It is the block's place in the source, not its depth, it holds for ints only, and sibling blocks share nothing either |
| M5 scalars | ignore declaration and scope | **Holds with one exception**, and spills do not always start at 0 |

Where M2 breaks, each pinned by a `pr_tie_` function:

- Three `int[2]` alone are not reversed (`pr_tie_three`).
- Two `int[2]` flip beside one `int` (`pr_tie_pair`).
- Plain `int`s flip beside larger locals (`pr_tie_small`).
- `int a; int b; short c; short d;` reverses the ints and not the shorts (`pr_tie_sizes`).
- A `double` tied with two arrays (`pr_tie_double`).
- Chars and shorts do not follow blocks (`pr_tie_scope_shorts`, `pr_tie_scope_sizes`).

**A local outside a tie changes the tie:** `pr_tie_three_int` only adds an `int` to `pr_tie_three`, and its three arrays take other offsets. So a table of orders by count cannot hold. I tried to name the mechanism by simulating a shell sort over every gap subset, a heap sort and a Hoare partition, each with ties swapping, on counts up to 13. None reproduces it, so I stopped there rather than fit one. That rules out only those simulations, not every sort.

**M5's exception:** in 20 twins differing only in declaration order, 19 gave identical code. Shorts spilled beside a short in memory differ under `-oneatx` (`pr_spill_short`). **Spills sort by size with the memory locals:** they sit above ints and arrays (`pr_spill_memory`) and below shorts (`pr_spill_small`).

## Decisions Made

- **The model refuses instead of guessing.** `order_is_known` is True when no two sizes tie, or when every local has one size of 1, 2 or 4, and only size 4 across blocks.
- **`Local.scope` is the line of the block's `{`,** 0 for the function's own block: only its order matters, and M4's key is source order.
- **Every struct is an unknown size.** The plan allows it, and a struct local with no `&` still sits in the frame, so any declaration whose size cannot be read sends the axis to plan 1's moves, not only an address-taken one.
- **A local the map does not show stays where it is** when the target is built, and one slot of a local places all of it: the map may show only `v[1]`.
- **`_BEFORE_ADDRESS` reads a unary `&`:** a cast before it counts, as in `(char *)&b`, and any other `)`, a `]` or a name leaves it binary.
