## Accomplishments

- `asm.case_notes` names each entry of a table in a data-in-code row, as a local `.L` label or the target's name. A bent table gets no note.
- `asm.annotated` lays notes on the matching `  0x<va>  ` lines. With no notes, or a note whose address has no line, the text is unchanged.
- `lift.call_notes` gives `eax=<expr> edx=<expr>` per call, a hole reading `h_<va>`. A refusal keeps the notes before it.
- `cmd_asm` reads the listing first, so its errors stay as they were. A lifter fault becomes one stderr line and the listing still prints.

### Auto-fixed Issues

**1. [Rule 1 - Bug] A table starts at the jump's own fixup and stops at the next table**
- **Found during:** Task 1, from a probe of both EXEs before the tests were written
- **Issue:** The plan says to read "that row's off32 fixups". 16 UFO2P and 10 TACP data rows hold several tables, so that would print another table's cases as fact.
- **Fix:** The same rule as `lift.find_tables`: start at `target_va`, stop at this row's next table or the holding row's end.
- **Files modified:** `tools/reverseapoc/asm.py`, `tests/test_asm.py`
- **Verification:** `test_case_notes_stop_at_the_next_table_of_the_row`, and the same case count as the lifter on all 168 real tables it reads
- **Committed in:** `7490a744`

**2. [Rule 1 - Bug] The table jump's operand is recognised by its real form**
- **Found during:** Task 1, same probe
- **Issue:** Every real table jump is `dword ptr cs:[eax*4 + N]`, with a `cs:` the plan's example lacks. TACP also has `cs:[eax + N]` with a fixup, which is no switch.
- **Fix:** `_TABLE_OPERAND` accepts the override and requires a scaled index with no base, as `Lifter.table_start` does.
- **Files modified:** `tools/reverseapoc/asm.py`, `tests/test_asm.py`
- **Verification:** `test_case_notes_read_a_jump_without_the_cs_override`, `test_case_notes_skip_a_jump_that_indexes_no_table`
- **Committed in:** `7490a744`

**3. [Rule 2 - Missing critical] A bent table gets no note (T-07.1-22)**
- **Found during:** Task 1
- **Issue:** `FixupIndex.overlapping` returns any field sharing a byte with the range, so row bounds alone do not check a table. A rel32 field is also 4 bytes.
- **Fix:** Every field must be an off32 on the table's grid, wholly inside the range, with no gap.
- **Files modified:** `tools/reverseapoc/asm.py`, `tests/test_asm.py`
- **Verification:** `test_case_notes_refuse_a_bent_table`, `test_case_notes_refuse_an_entry_past_the_row_end`
- **Committed in:** `7490a744`, test fixed in `6f4e1919`

**4. [Rule 1 - Bug] A call note shows only registers live at the call**
- **Found during:** Task 2, reading `Block_`
- **Issue:** The plan records every `ARG_REGS` register in `self.regs`. Every block starts with `r_<reg>` for each variable, so a register nothing wrote would print `edx=r_edx`. `keep_readers` also protects only needed registers, so a dead register's text can read a variable that has since changed. Either would be a guess read as fact.
- **Fix:** `note_values` keeps a register only if it is in `self.needed`, the live set at the call. A known but dead value, such as an `edx=3` nothing reads, is left out too: that loses a little and never misleads.
- **Files modified:** `tools/reverseapoc/lift.py`, `tests/test_lift.py`
- **Verification:** `test_call_notes_leave_out_a_register_the_lifter_only_named`
- **Committed in:** `2b233f20`

**5. [Rule 1 - Bug] The census guard does not depend on the cache file**
- **Found during:** Task 2
- **Issue:** The plan guards only when the cache file is absent, but `result_used` also rebuilds after a truncated file, which would walk every row in a live session.
- **Fix:** `call_notes` always holds the stem in `_BUILDING`. A good cache goes unread, which costs nothing because no register value depends on it. It also keeps the wrapper tests off the real `build/lift/`.
- **Files modified:** `tools/reverseapoc/lift.py`, `tests/test_lift.py`
- **Verification:** `test_call_notes_never_build_the_census[truncated]`
- **Committed in:** `2b233f20`

**6. [Rule 2 - Missing critical] A data-in-code row gives no call notes**
- **Found during:** Task 2
- **Issue:** `attempt asm <NAME>` accepts a data row, whose bytes only happen to decode. The `lift` verb already refuses one.
- **Fix:** `call_notes` returns `{}` for that kind.
- **Files modified:** `tools/reverseapoc/lift.py`, `tests/test_lift.py`
- **Verification:** `test_call_notes_are_empty_for_a_data_in_code_row`
- **Committed in:** `2b233f20`

**7. [Rule 1 - Bug] A case target names through `target_name(..., code=True)`**
- **Found during:** Task 1
- **Issue:** Plain `target_name` gives an address in no row a `D_` data name, though a case target is a branch destination.
- **Fix:** `code=True` prints the bare address instead, as `_operands` does for a branch.
- **Files modified:** `tools/reverseapoc/asm.py`
- **Verification:** by reading only: no test covers a case target in no row
- **Committed in:** `7490a744`

## Issues Encountered

- The plan says `callee` catches `StopIteration`, `AttributeError` and `RecursionError`. Today it catches `Unliftable` alone. `cmd_asm`'s `except Exception` covers the rest either way.
- Reaching a large row is slow: `attempt asm` took up to 20.78 s cold, because each run walks the signatures of the row's callees. The median is 0.1 s and no row faulted. See `## Seen, not built`.

## Seen, not built

- `contextpack.py` still reads the listing file, so the pack does not carry the notes.
- A disassembly of the agent's own object: `SKILL.md` L164 stays true.
- `.claude/skills/watcom-decomp/SKILL.md` L117-118 do not mention the notes yet: that is plan 6's update.
- A tail jump passes arguments too, and gets no register note.
- A table's `default:` target, known to the lifter as its guard, is not shown.
- A table in a game row prints as `dd` lines and gets no case note, and a table in the data object gets none either.
- A `.L` label a case note names has no `.LXXXXXXXX:` line unless a direct jump also lands there; its address line does exist.
- A cached or time-limited signature walk would cut the 20 s worst case of `attempt asm`.
- A row's refusal reason is not shown, so an agent cannot tell why notes stop partway.
