## Pattern Assignments

### `tools/reverseapoc/batch.py` (plan 1: stack mask and slot map)

**Where the mask goes** (`_tokens`, lines 233-243). The planner adds the stack rewrite here. Both `exact_text` and `form` come from this function, and nothing else builds tokens:

```python
def _tokens(code: bytes, va: int, masked: set[int]) -> list[tuple[str, str, int]]:
    out = []
    for insn in decode(code, va):
        hit = any(a in masked for a in range(insn.va, insn.va + insn.size))
        form = shape(insn.mnemonic, insn.op_str)
        exact_text = f"{insn.mnemonic} {insn.op_str}"
        token = form if (hit or insn.branch_target is not None) else exact_text
        out.append((token, form, insn.va))
    return out
```

**How to extend `Verdict`** (lines 326-339). New field goes after `exact_trim`, with a default, and with a comment saying it is a diagnostic:

```python
    # A diagnostic, never a match: exact once the row's trailing filler is cut off, ...
    exact_trim: bool = False
```

`Verdict(...)` is built positionally at lines 362, 365, 375 and 400, so an inserted field would shift those. `judge` computes the score at line 369; the masked score is a second `diff_summary`-style call beside it. `cell_record` (lines 426-437) picks keys by name, so existing JSONL stays stable unless a key is added on purpose. The raw `score` stays what it is: the frozen `near >= 90` bucket reads it.

**The module's rule to keep** (docstring lines 12-14): the score and key "only rank and diagnose; they decide nothing". The slot map follows that rule and holds offsets only, never bytes (lines 17-18).

**Section style:** `# ---- judge ----` banners group the module. Put the slot map under `# ---- diff summary (ranks and diagnoses, decides nothing) ----`.

**Test the mask with clean-room encodings** as `test_batch.py:29-32` does (see below).

**Four things the analogs do not settle, which the plan must pin:**

3. RESEARCH's byte-hash dedupe needs the function's bytes before `judge`, but only `judge` extracts them (lines 360-366). An object-file hash may differ for equal code. 4. D-26 acceptance: the statement-order axis is a candidate generator whose result stands only when `exact` is true. A statement-order variant with a higher score must not be kept as a reported result or as the base of a later wave's accepted output. This needs its own unit test. Statement reordering can change behaviour, so byte identity is the only evidence.

**Axis order** (RESEARCH "Consequences", extended by D-26): type first, then statement order, then scope, then declarations of address-taken locals and aggregates. Budget and seed are module constants (`SEED`, `BUDGET = 600`, as `sample.py:20-22` writes constants). No `--cell`, `--budget` or `--seed` (Pitfall 6).

**Validation:** `batch.read_ascii` and `batch.refusal` on the input through `_judged_text`, and `refusal` again on each generated text is unnecessary only if moves cannot add text; a test should show that.

**Source:** `batch.py:67-68`, `cli.py:1078-1087`
**Apply to:** all new modules. Raise `batch.BatchError` (a `ValueError`) with context in one place; the verb prints `reverseapoc <verb>: error: ...` and returns `EXIT_TOOL`. No silent `except`. A new exception class only where one already fits, as `Unliftable` does for the lifter.
