**Two findings are blockers, which differs from plan 02's review.** Nothing here can make a wrong match land, because `exact` is still the judge's verdict and only the gate claims a match. A draft like that will not compile to the row's bytes, so the bugs should cost matches as well as readability. No draft was compiled for this review, so that effect is reasoned, not measured.

The main concerns:

Reach counts come from instrumented runs over the 943 Tier 1 rows in the gate's order with shared `sigs`. They printed counts and addresses only, and no C or game byte left the process. The drive lock was free. A count means the pattern fired on that row, which is a token-level test: each count is a sound "this row has the shape", and an upper bound on rows whose bytes change. The 422 union comes from a warm run on the existing census (659 whole rows), and every other count from a cold run on a rebuilt census (661 whole rows). The suites were not run, and no draft was compiled for this review.

## Critical Issues

### CR-01: Statement text is built before the flush, so conditions, stores and call arguments read new values

**File:** `tools/reverseapoc/lift.py:1212` (`jcc`), `tools/reverseapoc/lift.py:867-879` (`write`), `tools/reverseapoc/lift.py:1250-1259` (`call`)

**Issue:** Each of these builds its text from an expression, then calls `flush` or `end_assign_jump`, which emit `r_x = ...;`, and then emits the old text after that assignment. The text now reads the new `r_x`, or repeats a memory read through it. Proved on stubs:

| Encoding | Draft |
|---|---|
| `dec edx; jne L`, L a merge | `r_edx = r_edx - 1; if ((r_edx - 1) != 0) goto L1006;` (a counted loop, stepped twice) |
| `cmp eax, edx; mov eax, 5; je L` | `r_eax = 5; if (r_eax == r_edx) goto L100A;` (compares 5, not the argument) |
| `mov eax, [eax]; test eax, eax; je L` | `r_eax = *(int *)((char *)r_eax); if ((*(int *)((char *)r_eax)) == 0) goto L1007;` (a list walk, dereferenced twice) |
| `dec dword ptr [esi + 4]; jne L` | the store, then `if (((*(int *)((char *)r_esi + 4)) - 1) != 0)`, which subtracts twice whenever the destination is memory |
| `mov eax, [eax]; mov [edx], eax; inc eax` | `r_eax = *...r_eax; *...r_edx = *(int *)((char *)r_eax);` |
| `mov edx, [edx]; call f` | `r_edx = *...r_edx; func(r_eax, *(int *)((char *)r_edx));` |

Reach over 661 whole-lifted rows: the `jcc` condition 337 rows, memory re-read after an `inc`/`dec`/arithmetic store 16, stored value 36, call arguments 35. SUMMARY said "how many rows it reaches was not measured". `switch` gets the order right, as SUMMARY says, because it reads the index after assigning.

**Fix:** Do the flush first, and let an assignment rebind the expressions it replaces, so a condition reads the variable:

```python
def assign(self, r, e):
    if e.text == f"r_{r}":
        return
    ...
    new = var(f"r_{r}", e.size, e.signed)
    self.regs[r] = new
    self.rebound[e.text] = new      # the text that now has a name

def jcc(self, ci, mn):
    self.flush(ci)
    self.end_assign_jump(ci)
    c = self.cond(mn)               # after the assignments; cond reads through self.rebound
```

`write` and `call` take the same order: flush, then build the text through `rebound`. An operand that really is overwritten before the jump (`cmp eax, edx; mov eax, 5; je L`) has no name left, so it goes through a temporary or raises `Unliftable("flags: operand reassigned before the jump")`. It must never print. Tests first: one per table row above, plus `test_a_counted_loop_steps_once`.

### CR-02: Assigning a variable leaves stale readers, so aliases, swaps and slots read the wrong value

**File:** `tools/reverseapoc/lift.py:727-732` (`assign`), `tools/reverseapoc/lift.py:1274` (`call`), `tools/reverseapoc/lift.py:872-875` (`write`), `tools/reverseapoc/lift.py:914-919` (`end_assign`)

**Issue:** A register's expression is text over C variables. `assign` overwrites `r_x` without looking at which other registers still read `r_x`, and the same goes for `r_eax = f(...)` and a store to a scalar slot. A slot read is `pure` and an atom (line 134), so `flush` never touches it. `end_assign`, `end_assign_jump` and `switch` assign in sorted name order as if the copies were sequential, but they are a parallel copy. Proved on stubs:

| Encoding | Draft |
|---|---|
| `mov ebx, eax; call f; add eax, ebx; ret` | `r_eax = func(...); return r_eax + r_eax;` |
| `mov ecx, eax; mov eax, [eax]; mov [edx], ecx` | `r_eax = *...r_eax; *...r_edx = r_eax;` (stores the next node, not the node) |
| `mov ecx, eax; mov eax, edx; mov edx, ecx`, then a merge | `r_eax = r_edx; r_edx = r_eax;` (the swap loses `eax`) |
| `mov eax, [esp + 8]; mov [esp + 8], edx; ret` | `s_8 = r_edx; return s_8;` |

Reach over 661 whole-lifted rows, where the reader is live afterwards: 193 rows across `assign`, 78 across a call's result, 59 across a slot store. `test_a_store_through_the_array_keeps_its_order_with_a_read` pins this rule for arrays, whose reads are impure, and scalars never got it. `pushes` and `fstack` hold expressions the same way; SUMMARY names the float side, and this review proved neither one on a stub. Together with CR-01 this reaches 422 of 659 whole-lifted rows.

**Fix:** Give `assign` one rule. Before it overwrites a name, every other live register reading that name becomes its own variable first, with a temporary breaking a cycle:

```python
def keep_readers(self, name: str, r: str) -> None:
    for other, e in list(self.regs.items()):
        if other != r and re.search(rf"\b{name}\b", e.text):
            self.assign(other, e)      # a swap's cycle goes through t_<r>
```

`call` runs the same step for `r_eax` before it emits `r_eax = ...;`. A store to a scalar slot does it for the slot's name, and it is simplest for `slot` reads to be `pure=False` so that `flush` covers them. Tests first, one per table row.

## Warnings

### WR-01: The census differs by who asks first, so one row's draft changes between runs

**File:** `tools/reverseapoc/lift.py:1386-1423`, `tools/reverseapoc/lift.py:287`, `tools/reverseapoc/lift.py:1407`

**Issue:** `result_used` runs on the caller's `sigs`. While it builds, `_BUILDING` makes it return `None`, so every signature computed inside skips the `returns = False` demotion, and those undemoted signatures stay in the shared dict. Proved on a stub: row A calls B, then D; cold, the draft declares `int func_D(void);`, and warm, `void func_D(void);`.

Over Tier 1, in the gate's order, the cold pass and the warm pass differ in text on **88 of 661** rows, for example ufo2p 0x00010300, 0x00011430 and 0x0001DD80. The file also carries no provenance:

- `cache.is_file()` trusts any file of that name. A census rebuilt today differs from the `build/lift/` copy for both EXEs, and those copies give 659 whole rows where the rebuilt census gives 661. Until Task 4 deletes them, the `lift` verb reads a census from an older lifter.
- `reverseapoc lift` passes `sigs=None`, so it never shares `sigs` as the gate does. The verb's draft can differ from the draft the gate measured for that row.
- Mutual recursion stays order-dependent, which truth 3 does not cover: with A calling B and B calling A, A's signature is `nregs=0` with A first and `nregs=2` with B first. Proved on a stub.

**Fix:** Build the census on private `sigs`, proved on the stub (cold now equals warm):

```python
lf = Lifter(exe, row, census_sigs)   # census_sigs = {} at the top of the build, never the caller's
```

Drop the `sigs` parameter of `result_used`. Store the EXE's hash and the SHA-256 of `lift.py` in the JSON, and treat a mismatch as no cache. Test first: `test_a_cold_census_gives_the_warm_draft`.

### WR-02: The census write is not atomic, a bad file is a traceback, and a failed build disables the demotion for the process

**File:** `tools/reverseapoc/lift.py:1398`, `tools/reverseapoc/lift.py:1401-1421`, `tools/reverseapoc/cli.py:1315-1324`

**Issue:** Three proved faults in one function:

1. `cache.write_text` bypasses `fileio.write_atomic`, which that module's docstring says every generated file goes through.
2. A truncated file raises `JSONDecodeError`. That is a `ValueError`, not in `_ERRORS`, so `reverseapoc lift` ends in a traceback rather than exit 2. A file with the wrong keys raises `KeyError` the same way.
3. `_BUILDING.discard(stem)` is not in a `finally`. After an exception escapes the build, `_BUILDING` stays `{'stub'}`, `result_used` returns `None` for the rest of the process, and no later signature is demoted. `measure_curve.lifted` catches `Exception` and carries on, so a gate run would continue on that footing.

**Fix:** `write_atomic(cache, json.dumps(...).encode("ascii"))`; wrap the read so a bad file is treated as no cache, or raises `Unliftable` with the path; and use `try: ... finally: _BUILDING.discard(stem)`.

### WR-03: `pop` restores nothing and `add esp` is ignored with pushes pending

**File:** `tools/reverseapoc/lift.py:924-931`

**Issue:** `step` treats every `pop` as an epilogue pop: it moves `esp` and writes no register, and `self.pushes` keeps the value. `mov ecx, edx; push eax; mov eax, 1; pop eax; ret` drafts `return 1;`. Proved. `add esp, N` with a push pending is a silent no-op, so `esp` stays low and later slots get the wrong names: after `push eax; call f; add esp, 4`, `mov eax, [esp]` reads `s_14` where the frame's `s_10` is meant. Proved, and the pushed value disappears from the draft.

Reach over 661 whole rows: 13 rows have a `pop` outside an epilogue, 8 have the `add esp`.

**Fix:** `pop` takes the top of `self.pushes` into its register when one is pending, and raises `Unliftable("pop: value not pushed in the block")` when the `pop` is not an epilogue's. `add esp, N` drops `N // 4` pending pushes and always moves `esp`.

### WR-04: Low-byte and word reads are the full register, and low writes drop the upper bytes

**File:** `tools/reverseapoc/lift.py:689`, `tools/reverseapoc/lift.py:712-714`, `tools/reverseapoc/lift.py:1497`

**Issue:** `get("al")` returns eax's text with `size=1` and no narrowing, and no reader looks at `size`. `call f; test al, al; sete al` drafts `r_eax == 0`, a test of all 32 bits. `set("al", ...)` replaces the whole register: `mov eax, edx; mov al, 1; ret` drafts `return 1;`, and `mov eax, edx; add al, 1` drafts `return r_edx + 1;`, carrying into `ah`. Proved. `_use_def` counts only a high-byte write as a use, where the plan's Task 2 says "a partial write is a use and a def of its full register".

`test_high_byte_read_is_a_byte_of_any_register` starts from `mov eax, 0`, the one case that hides this.

Reach: 231 of 661 whole rows compare or test a sub-register of a register whose value is 32 bits wide. That is an upper bound on wrong semantics, because the upper bytes may be zero there, but the C still asks for a wider compare than the row has, so it costs bytes either way.

**Fix:** `get` of a low part wraps a non-constant, full-width value in `(unsigned char)` or `(short)`. `set` of a low part, when the old value is not 0, merges as `with_high_byte` does, and `_use_def` counts that write as a use. This changes liveness as the high-byte rule did, so re-check the void-callee count that rule fed.

### WR-05: `__cdq(...)` reaches 52 drafts as a call to a function that does not exist

**File:** `tools/reverseapoc/lift.py:984`, `tools/reverseapoc/lift.py:1141`

**Issue:** The comment says "only idiv may read it", and nothing enforces it. `cdq; xor eax, edx; sub eax, edx; ret` drafts `return (r_eax ^ (__cdq(r_eax))) - (__cdq(r_eax));`, and `mov edx, eax; sar edx, 31; add eax, edx` does the same through line 1141. C89 lets the call compile as an implicit function, so the row can reach `compiled` with a relocation to a symbol that does not exist. 52 of 661 whole-lifted drafts hold it, and none of those can be exact.

**Fix:** Mark the value (`E.sign_of`, or a sentinel class) and have `get` raise `Unliftable("op: cdq")` for any reader but `divide`. The abs and divide-by-2 idioms then show up in the refusal table with a name, and D-17 decides whether to build them.

### WR-06: Flags are wrong after `sub`, `not` and `xor r, r`

**File:** `tools/reverseapoc/lift.py:1161-1174`, `tools/reverseapoc/lift.py:973`, `tools/reverseapoc/lift.py:1115-1122`

**Issue:** Three proved cases:

1. After a result, an unsigned condition compares the result with 0, which is not what the carry means. `sub eax, edx; ja L` drafts `((unsigned)(r_eax - r_edx)) > 0`, which is `a != b`, and `jb` drafts `... < 0`, which is always false. SUMMARY names only the `jb` half. 7 of 661 whole rows.
2. `not` changes no flag on x86, but line 973 sets `("res", e)`, so `cmp eax, edx; not ecx; je L` drafts `(~r_ecx) == 0`.
3. `xor r, r` returns at line 1122 and leaves the old flags, so `cmp eax, edx; xor ecx, ecx; je L` drafts `r_eax == r_edx` where the jump is always taken.

**Fix:** For `sub` keep the operands: `self.flags = ("cmp", a, b)`, which is exact for every condition. For any other result an unsigned condition raises `Unliftable("jcc: carry of a result")`. Line 973 applies to `inc`, `dec` and `neg` only. The `xor` path sets `("res", const(0))`.

### WR-07: Compares take the wrong signedness from their operands

**File:** `tools/reverseapoc/lift.py:127-130`, `tools/reverseapoc/lift.py:843`, `tools/reverseapoc/lift.py:975`

**Issue:** Proved cases:

- `cmp` reads memory as signed whatever the condition, so `cmp byte ptr [D], 0FFh; je L` drafts `(*(signed char *)...) == 255`, which is never true.
- `cmp byte ptr [D], 80h; jb L` drafts `((unsigned)(*(signed char *)...)) < 128`, which sign-extends first.
- `const` writes values at or below -4096 in hex, which is unsigned in C. `cmp eax, -5000; jl L` drafts `r_eax < 0xffffec78`, an unsigned compare where the row has a signed one. This one reaches 1 Tier 1 row. The byte and word cases were not counted.

**Fix:** Pass the condition's signedness to the `cmp` read, or read narrow memory as unsigned and let a signed condition cast. Mask the immediate to the operand's width for an unsigned read. In `const`, print a negative value as decimal, using `(-2147483647 - 1)` for `INT_MIN`.

### WR-08: `param_types` narrows a parameter the row uses at full width

**File:** `tools/reverseapoc/lift.py:500-530`, `tools/reverseapoc/lift.py:566`

**Issue:** Only register operands count as reads, and only in the entry block. `mov dl, al; mov ecx, [eax]` drafts `unsigned char r_eax` and then dereferences it, because a base register in a memory operand is not a read. `test al, al; je L; mov eax, [eax]` narrows the same way, because the full read sits in the next block. Both proved: the pointer is truncated to a byte. Line 527 also decides a word's signedness from any `movzx` in the block, whatever register it reads. Reach was not counted.

**Fix:** Count `m.base` and `m.index` as full-width reads, and walk every block until the register is written, or narrow only when the row has one block.

### WR-09: A table guard folds without checking what it compares

**File:** `tools/reverseapoc/lift.py:397-407`, `tools/reverseapoc/lift.py:1208-1211`

**Issue:** `table_guard` accepts any `cmp x, imm; ja` as the last control flow before the jump. `cmp ebx, 5; ja D; jmp [eax*4 + T]` drafts `switch (r_eax)` with `default: goto D`, and the test of `ebx` is gone. Proved.

12 of the 62 Tier 1 guards compare something other than the index register. Most of them are probably the same value moved first, so 12 is rows left unverified, not rows known to be wrong. The docstring's claim and `test_a_guard_some_instructions_before_the_jump_still_folds` do not separate the two.

**Fix:** During the run, fold only when the compare's left operand and the switch index are the same expression. Otherwise keep the `ja` as a plain `if`. Test first with the encoding above.

### WR-10: Broad silent excepts hide bugs as an unknown signature or a shorter census

**File:** `tools/reverseapoc/lift.py:342`, `tools/reverseapoc/lift.py:1409`

**Issue:** `except Unliftable, StopIteration, AttributeError, RecursionError:` turns a programming error into `sig = None` or a row dropped from the census, with no trace. `.claude/rules/tools.md` says never a silent `except`. SUMMARY's deviation 2 removed `KeyError` from this list for that reason, and `AttributeError` carries the same risk. `StopIteration` has no source on these paths: `signature` and `prepare` call no `next`. `RecursionError` records `None` for whichever row hit the limit, which depends on the depth of entry.

**Fix:** Catch `Unliftable` alone. If `RecursionError` is measured to occur, convert it to `Unliftable("call: chain too deep")` at the one place that recurses.

### WR-11: A recursive row declares itself with `int` types its own definition may not have

**File:** `tools/reverseapoc/lift.py:1260-1264`, `tools/reverseapoc/lift.py:597`

**Issue:** `call` adds a prototype for every callee, including the row itself. A self-call drafts `int func_00001000(int);` above `unsigned char func_00001000(unsigned char r_eax)`, a conflicting redeclaration. Proved as text; not compiled for this review. 3 Tier 1 drafts declare themselves and 2 of those conflict, so these rows should land in `compile-failed` for a reason the SUMMARY's E1151 line does not name.

**Fix:** In `lift`, drop the entry for the row's own name before writing `externs`: the definition is its own declaration for anything after it, and calls sit inside it.

### WR-12: A scalar slot keeps its first access's type, and a saved register reads as a local

**File:** `tools/reverseapoc/lift.py:819-823`

**Issue:** `locals.setdefault` keeps the first width and `var` ignores the rest. `mov byte ptr [esp + 8], al; mov eax, [esp + 8]` drafts `signed char s_8;` and returns it as if it held all four bytes. Proved. SUMMARY notes the float and integer case only. Offsets in `[frame_top, 0)` are the saved registers, and `slot` makes them locals: `push ebx; mov eax, [esp]` drafts an uninitialised `int s_4;`. Proved. Reach was not counted.

**Fix:** Refuse a slot read wider than its declaration with `Unliftable("stack: slot read at two widths")`, unless the short hint covers it, and refuse `frame_top <= off < 0` with `stack: saved register slot`.

### WR-13: Six shapes emit wrong text silently, none on a Tier 1 row today

**File:** `tools/reverseapoc/lift.py:572`, `:614-616`, `:249-250`, `:928`, `:1480-1481`, `:375-377`, `:969`, `:308`

**Issue:** Each one was proved on a stub except the sixth, which comes from reading. Each measured 0 Tier 1 rows, so they matter for the later tiers, not for this curve. A silent wrong answer is still worse than a refusal.

1. A jump to the first block has no label and the entry block is no merge: `dec eax; jne start; ret` drafts `if ((r_eax - 1) != 0) goto L1000;` with no `L1000`, and the `dec` is lost.
2. `sub esp, eax` and `add esp, ecx` read `.imm` of a register operand, which is the register's capstone id: `frame` takes 0x13 as the frame size and the draft reads `s_13`.
3. `lea r, [r + D]` with a fixup and a zero field passes `_self_move` as filler and disappears from the draft.
4. A table entry with no fixup leaves a silent gap (`case 0`, `case 2`), against `table_cases`' docstring that a bent table is no table.
5. `neg` of a negative constant prints `--5`.
6. `data_name` keeps a name's trailing `_`, which `callee` strips at line 335, so the address of a runtime function names another symbol.

**Fix:** In order: let `merge` include `order[0]` when it has a predecessor, and give it a label. Check `operands[1].type == X86_OP_IMM` and refuse otherwise. Skip `_self_move` when a fixup sits on the displacement. Return `{}` unless the keys are `range(len(fields))`. Parenthesise the operand in `neg`. Share the stripping between `callee` and `data_name`.

### WR-14: The real tests read and write the live census
