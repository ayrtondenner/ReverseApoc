## Warnings

### WR-01: `slot` ignores what was masked before the stack mask, so a wrong target can route to the search

**File:** `tools/reverseapoc/classify.py:74-78`, `tools/reverseapoc/classify.py:88-89`, `tools/reverseapoc/classify.py:38-39`

**Issue:** `batch.tokens` shows a branch target or a relocated operand as `N` (`batch.py:288`) before any class is chosen. Equal tokens are kept away from `slot` by the `a != b` guard, but one differing stack offset opens the ladder, and then everything those masks hid is ignored. `_class_of` also holds `reloc.ok` and drops it. Proved on stubs:

| Pair | Class | What really differs |
|---|---|---|
| `je +2` / `je +3` with `[esp + 4]` / `[esp + 8]` | `slot` | control flow: the jump lands on another instruction |
| `mov eax, 1` / `mov eax, 2` in a relocated field, with the same stack difference | `slot` | the relocation target |
| `add esp, 8` / `add esp, 0xc`, equal `sub esp` | `slot` | no slot at all: `_frames` reads only `sub esp`, while the mask also hides `add esp` |

Without the stack difference the first two are `mixed`. `slot` is the only class that changes a route, and the search permutes declarations, which reaches none of these. SUMMARY's deviation 1 gives this reason itself: "a declaration search cannot fix a relocation". The plan's threat table names this risk: "a wrong route sends a row to the wrong tool".

**Reach:** 0 of 1,513 objects are `slot`, so this moves no count today. It matters as soon as the converter gets closer, because near misses are the rows that reach this path.

**Fix:** let `slot` mean what truth 2 says, that stack offsets are the only difference.

```python
_FRAME = ("sub esp, ", "add esp, ")  # str.startswith takes a tuple


def _jump_shape(code: bytes, va: int) -> list[int | None]:
    """Each jump's target as an instruction index, so a shifted body still compares equal."""
    insns = list(batch.decode(code, va))
    index = {insn.va: n for n, insn in enumerate(insns)}
    return [index.get(i.branch_target) for i in insns
            if i.branch_target is not None and not i.is_call]
```

In `classify_pair`, a `slot` whose `_jump_shape` differs falls through to the length fallback. In `_class_of`, return `mixed` for a `slot` when `not reloc.ok`.

### WR-02: `_strict_prefix` reads an empty list and a stopped decode as `tail`

**File:** `tools/reverseapoc/classify.py:42-43`, `tools/reverseapoc/classify.py:70`

**Issue:** `long[:0] == []` is always true, so an empty token list is a strict prefix of any other. `x86.decode` also stops silently at a byte capstone cannot read, so a token list can end before its bytes do. Neither case means one body is the other plus a tail. Proved on stubs:

| Pair | Class | Tokens | Bytes |
|---|---|---|---|
| empty `ours` against a full body | `tail` | 0 / 6 | 0 / 13 |
| same prefix, `theirs` undecodable after it | `tail` | 8 / 3 | 16 / 16 |

The second pair has equal byte lengths and real code on both sides. `judge` guards the first case for its own filler check (`0 < n < length`, `batch.py:557`), so an empty body is already an expected input there. `classify_pair` has no such guard.

**Reach:** 0 of the 1,513 objects decode short, and the route does not change, because `tail` is not special in `route`. The exposure is the 55 game rows whose bytes do not decode to the row's end (21 in ufo2p, 34 in tacp), which is an upper bound. The same stop makes a pair compare equal up to the stop and hides any difference after it, which also yields a false `slot`: proved with one stack offset differing before an undecodable byte and different code after it (16 and 18 bytes).

Separately, all 4 `tail` records on disk come from the prefix branch and none has a filler tail: `ours` stops 4, 6, 33 and 35 instructions early. The plan allows this, but a row missing 35 instructions is a truncated draft, and the class name reads as trailing filler.

**Fix:**

```python
def _strict_prefix(short: list[str], long: list[str]) -> bool:
    return 0 < len(short) < len(long) and long[: len(short)] == short


def _decodes_whole(code: bytes, va: int) -> bool:
    return sum(insn.size for insn in batch.decode(code, va)) == len(code)
```

After the `exact_trim` check, a pair where either side fails `_decodes_whole` goes straight to the length fallback.

### WR-03: `size` is a catch-all, so the class table will not say what the plan wants it to say

**File:** `tools/reverseapoc/classify.py:72-73`, `tools/reverseapoc/classify.py:78`

**Issue:** The plan's purpose is that a first-difference `key` "reads 'frame or save set' for most rows", while masks "do say it". On the objects on disk the ladder says very little:

| Class | Objects |
|---|---|
| `size` | 1,376 (91%) |
| `mixed` | 126 |
| `register` | 6 |
| `tail` | 4 |
| `branch` | 1 |
| `slot` | 0 |

The 1,376 `size` records split into 762 with equal frames, which reach line 78 only because no mask fit and the byte lengths differ, and 614 whose frame differs. All 614 also get `None` from `_widest_mask`, so the frame is never the only difference. **No `size` record on disk is explained by any mask.** In practice the class means "does not fit, and is not the same length", which is what `mixed` means, and a different length is the normal result of a body that differs at all. 1,279 of the 1,376 score under 70.

This code follows the plan: step 5 and truth 2 both ask for it, so it is not a code defect. It is reported because the owner reads this table, and "91% size" invites a reading (frames are the problem) that the data does not support. No route changes.

**Fix:** an owner ruling, before point 4's table is read as a diagnosis. One option is to keep `size` for a differing frame and send step 5's fallback to `mixed`, which gives `size` 614 and `mixed` 888 here. That changes truth 2 and `test_different_length_is_class_size`, so it is not the fixer's to take alone. If the ruling keeps the classes, say in the curve's section and in `docs/toolchain.md` that `size` means "no mask fits", not "the frame is wrong".

### IN-01: The register mask collapses operand widths

**File:** `tools/reverseapoc/classify.py:30`, `tools/reverseapoc/classify.py:50-51`

**Issue:** Every width reads `R`, so a type difference reads as a register choice. Proved: `test al, al` / `test eax, eax`, `movzx eax, al` / `movzx eax, ax`, `mov al, bl` / `mov eax, ebx` and `mov ax, bx` / `mov eax, ebx` are all class `register`. The cause is `char` against `int`, which no allocator decides. All 6 `register` records on disk still agree under a width-aware mask, so this is latent and moves no route.

**Fix:** mask per width (`R8`, `R16`, `R32`), so those pairs read `mixed` or `size`.

### IN-02: An `exact_trim` row under 90 routes to an agent

**File:** `tools/reverseapoc/classify.py:84-92`

**Issue:** `exact_trim` means the bytes already match and the rest is "a unit-boundary question" (`batch.py:577-579`), so an agent has nothing to change in the C. A short row falls under `NEAR` on its filler alone. Proved: `xor eax, eax; ret` against the same plus three `mov eax, eax` scores 57.14 and routes to `agent`. The route table is pinned by the plan, and 0 records on disk have `exact_trim`, so this is noted and not a defect in the code.

**Fix:** if such rows appear, route `exact_trim` to `converter` beside the near rows, which is a one-line change to the table and needs the plan's agreement.
