## Decisions Made

- **Point 0 differs from RESEARCH's table, and it was not tuned.** See "Curve point 0" below.
- **`scope_moves` keeps no first-use rule.** NHL95PC's `scope_decls.py` keeps a move only when the first use in the block assigns the variable. That would drop arrays and address-taken locals, which RESEARCH's table says scope moves. A non-exact scope winner can therefore change meaning, and only bytes prove anything.
- **`body_key` also hashes each fixup's `displacement`,** which the plan's (offset, target name) leaves out: two objects can differ only there, and a shared verdict would then be wrong.
- **`TYPE_MOVES` has keys for `char` and the `common.h` typedefs,** which committed C uses for locals. Values stay within the plan's six types. Pointers, arrays, struct locals and parameters do not move.
- **`declarations` returns line numbers, and splitting is a separate `split_declarators`,** because the moves work on lines. `best.c` shows one declarator per line even when the base wins.
- **Declarations are read on blanked text,** through `contextpack._blanked`. `static` and `extern` locals are left out: they hold no stack slot.
- **A base that fails to compile does not stop the search:** it scores 0 and the moves still run. A file that does not define the function is exit 2, before the row's output is cleared.
- **Rounds repeat while one improves the base.** The plan says a second round when an axis improved; the same loop allows a third, and `BUDGET` and the seen texts end it.
- **Curve table choices:** the `plan` cell of point 0 is `none`. A sample row keeps counting in the sample table if it matches later, so `s exact` cannot fall because of a landing. The matched line folds `near` into `compiled`. `next_streak` is one small helper beside `stop_line`.

- NHL95PC `scope_decls.py` scores combinations of the moves that helped and tries every enclosing block; `scope_moves` is one move to the innermost block.
- NHL95PC `permute_decls.py` also moves whole multi-line `struct { ... } name;` declarations; `declarations` reads one line each.

- `slot_map` tracks only the first `sub esp, N`: a later one, as a struct passed by value may need, shows up as a conflict.
- `_block_stacks` reads a line from its start, so a use in `} while (c);` counts as inside the block; that scope move fails to compile and costs one job.
- `_in_memory` takes a bitwise `&` before a name as address-taken, which only reorders the moves; plan 2's `memory_locals` is the real reading.
- `search_sample` in `measure_curve.py` has no pytest: the phase script's self-check covers only the join, and a scratch run on two real rows checked the rest.
- `_tokens` gives `ret ` with a trailing space when unmasked and `ret` when a relocated field touches it, so a no-operand instruction under a mask compares unequal to itself; existing behaviour, left alone.
- `judge` now runs difflib twice per object, for every `batch` and `judge` caller, not only `search`; not measured.
- `search` leaves every `v<nnnn>/` under build/batch/search/, up to 600 objects per row; nothing prunes them.
- RESEARCH's reference table (16 exact) carries the cross-EXE `sigs` leak; RESEARCH was left as it is.
