## Summary

The review covers plan 07.1-01's `tools/` and `tests/` changes from `44f85a4b` to HEAD. `search.py` is new, and `batch.py`, `cli.py`, `flags.py` and their tests were extended. For the two large files, `flags.py` and `tests/test_flags.py`, the review read the phase diff, the batch-proposal code and every consumer of `evidence`, not the whole file.

No finding is a blocker. Nothing here can make a wrong match land, because `exact` is still `check`'s own verdict and only the gate claims a match. The `judge` refactor (`function_body`, `unjudged`, `_reloc_mask`) keeps the old failure keys and verdicts. Wave and cell indexing, budget accounting, the `seen` dedupe, termination, `stands`, and the `with_source` and `propose_batch` route all traced clean.

The main concerns:

- **The stack mask misses two common frame idioms (WR-02, WR-03).** A scan of the 3,068 game rows of both EXEs finds `mov r, esp` in 335 rows and `[ebp - N]` locals in 84 rows. The mask is the search's primary rank, so this weakens the ranking on those rows.
- **D-26 has a gap on the declaration axis (WR-01).** Initializers can be reordered by a variant that is not exact.
- **Search's fixed results path defeats the "only new evidence" rule (WR-04).** A rejected proposal blocks every later result for that row and rule.

Each claim marked "proved" was run in a scratch probe outside the repo, against the real modules. The row counts come from a read-only decode of `orig/`. The full suites were not run for this review.

YAGNI lens: `reverseapoc search` has only the options the plan names (exe, address, file, `--orig`, `--manifest`, `--config`, `--cflags`, `--watcom-dir`). There is no single-implementation abstraction. Two later-use items are recorded, IN-01 and IN-02.

## Warnings

### WR-01: The declaration axis reorders initializers, so a non-exact statement reorder stands (D-26 gap)

**File:** `tools/reverseapoc/search.py:293-320` (also `:264-269`, `:349-352`)
**Issue:** `declaration_moves` and `_shuffles` swap whole declaration lines, initializers included. Proved: from `int b = g(); int c = h();`, the first move is `int c = h(); int b = g();`, tagged `("declaration",)`. The two calls now run in the other order. `_Scored.stands` only looks for `statement` in the axes, so this variant can become the base and the reported winner without being exact. That is the case D-26 and the module docstring rule out: "reordering can change behaviour, so byte identity is the only evidence".

`scope_moves` has the same effect on an initialized local. Proved: `int c = 0;` moves into a `while` body, so the initializer runs on every iteration. The SUMMARY accepts that a scope winner can change meaning, but not this as a route around D-26.

Reach is small today. Committed `src/` holds one initialized local and none with a call, and lifter drafts have none. Only a non-exact `best.c` or a base is affected, never a match.
**Fix:** Tag a move that changes the relative order of initializers with `statement` too, so D-26's existing rule applies:

```python
def _initialised(found: re.Match[str]) -> bool:
    return "=" in found["declarators"]

# in declaration_moves, for a pair, and in _shuffles, for a block holding an initializer:
axes = ("declaration", "statement") if touches_initialiser else ("declaration",)
```

Do the same in `scope_moves` for an initialized declaration. Add a test in the shape of `test_statement_variant_with_a_higher_score_is_dropped`.

### WR-02: The stack mask and the slot map miss `mov r, esp`, the address of slot 0

**File:** `tools/reverseapoc/batch.py:238-247`, `:328-342`
**Issue:** `_stack_masked` says `[esp]` is slot 0, but Watcom takes the address of slot 0 with `mov r, esp`, not `lea r, [esp]`. The real EXEs show the pair side by side, for example `lea eax, [esp + 0x38]` then `mov ebx, esp`. The scan finds this in 172 UFO2P and 163 TACP game rows, about a quarter of the rows with a `sub esp` frame.

These are address-taken locals, the locals declaration order moves. A slot swap involving slot 0 therefore does not meet `stack_score`'s docstring promise ("differ only in stack offsets and frame size score 100"). Proved: `sub esp,0x10; mov eax, esp; call; add esp,0x10; ret` against the same body with `lea eax, [esp + 4]` scores `stack_score` 80.0, equal to the raw score. `slot_map` reports `pairs=()`, because `_ESP_OPERAND` needs a bracket, so the swap never appears in the map either.
**Fix:** Normalise the idiom in both readers, leaving `mov ebp, esp` alone:

```python
_ESP_COPY = re.compile(r"^mov (?!ebp)(?P<reg>e[a-z]{2}), esp$")

def _stack_masked(token: str) -> str:
    token = _ESP_COPY.sub(r"lea \g<reg>, [esp + N]", token)
    ...
```

In `_frame_slots`, read the same instruction as displacement 0. Add a pinned pair to `test_stack_mask_*` and `test_slot_map_*`.

### WR-03: `ebp`-framed functions get no stack mask and report an empty map as a bijection

**File:** `tools/reverseapoc/batch.py:238`, `:345-357`; `tools/reverseapoc/cli.py:1264`
**Issue:** The mask and the slot map read only `esp`. Across both EXEs, 185 game rows hold `mov ebp, esp`, and 84 address locals as `[ebp - N]`. On those 84 rows `stack_score` reduces to the raw score apart from `sub esp, N`, so D-01's "masks stack offsets first" silently does not apply. `slot_map` then returns `pairs=()` and `bijection=True`, because `len(pairs) == 0` satisfies the test, and the verb prints `slots: bijection True`. That reads as a clean permutation when nothing was compared. The same line appears for a body that failed to compile.

The lifter refuses real `ebp` frames, so this reaches agent-written C rather than converter drafts.
**Fix:** When `mov ebp, esp` opens the body, treat `[ebp - N]` as a slot in both readers. `ebp` is also a general register in this code (RESEARCH: 66 false refusals), so do not mask `ebp` unconditionally. Separately, print `slots: none compared` when `pairs` is empty instead of a bijection result.

### WR-04: A rejected search proposal blocks every later search result for that row and rule

**File:** `tools/reverseapoc/flags.py:863-866`; `tools/reverseapoc/search.py:468`, `:452`
**Issue:** `_group_skip` treats `rel in p.evidence` as "same evidence", and its comment says "only new evidence brings it back to the owner". A `batch --out` path can differ between runs, but search always writes `build/batch/search/<stem>/<addr8>/results.jsonl`, so `rel` never changes for a row. Proved on `batch_repo`: F-0001 was rejected, a later search found a different exact winner under the same cell, and `propose_batch` added nothing, skipping it as "was rejected on build/batch/search/ufo2p/00010000/results.jsonl". The new C can never reach the owner. The message is also wrong, because that file now holds other content.
**Fix:** Compare content as well as the path. Run the rejected check after `_batch_candidate` and require the same candidate:

```python
rejected = next((p for p in unit_ps if p.rule == rule and p.status == REJECTED
                 and rel in p.evidence and p.candidate_sha256 == lf_sha256(text)), None)
```

Add a test that re-proposes a different winner from the same path.

### WR-05: The source reader does not drop directives or dead branches, so a search can walk dead text

**File:** `tools/reverseapoc/search.py:110-139`
**Issue:** `_code` blanks comments and literals only. `contextpack.definitions` also removes directives and `#if 0` branches through `_live`, and the D-12 parser accepts `#if 0`. Proved: with a dead copy of the function in `#if 0` above the live one, `function_span` returns the dead copy's lines, so every move edits text the compiler never sees. Each variant then compiles to the same body, and the run ends with exit 1 and no warning. Proved too: `#define f(x) { x; }` before `int f(int a)` gives span `(0, 0)`, which yields no moves.

Committed `src/` holds no `#if 0` today, so this reaches hand-kept drafts only, but the failure is silent.
**Fix:** Read through the same phases as `definitions`, and turn `cfg._ConditionalError` into a `BatchError`:

```python
def _code(text: str) -> str:
    cfg = check._configure()
    flat, joined = contextpack._blanked(text, cfg)
    return contextpack._live(flat, joined, cfg.code_text(text))
```

`definitions` passes `_blanked` normalised text, so confirm that `run_search`'s LF text needs no further step and that columns stay aligned for `_split_line`.

### WR-06: One object that fails conversion aborts the whole search and loses the best variant

**File:** `tools/reverseapoc/search.py:355-365`, `:444-455`; `tools/reverseapoc/batch.py:463-467`, `:500`
**Issue:** `function_body` catches `OSError`, `CheckError` and `OMFError` around `parse_module` only. `defined_functions` runs `convert(module)` outside that `try` and can raise `Omf2ElfError`, and `with_relocs` can raise `RelocError`. Neither is caught in `_verdict`, so one bad variant ends the run with exit 2. `best.c` is written only at the end. Proved with an injected `Omf2ElfError`: the error propagates and no `best.c` exists. `measure_curve.search_sample` has no guard either, so it would stop the curve point.

No real trigger has been seen, and the 41-row dry run had no crash. The docstring still promises that a failed variant "only scores 0", and the search exists to feed the compiler text nobody wrote.
**Fix:** Score such a variant as unjudged, and let the search continue:

```python
try:
    ...
except (omf2elf.Omf2ElfError, relocs.RelocError) as exc:
    return batch.unjudged(run.row.end - start, f"not judged: {exc}")
```

Guard `function_slots` in `_result` the same way, or move the widened `except` into `batch.function_body` so `judge` gains it too.

### IN-01: YAGNI: `SearchResult.text` has no production reader

**File:** `tools/reverseapoc/search.py:87`
**Issue:** Later-use code. `cli.py` reads `best`, and `measure_curve.py` reads `records`. Only tests read `text`, and it duplicates `best.c`, which the record's `source_sha256` already pins.
**Fix:** Remove the field, and have tests read `result.best`.

### IN-02: YAGNI: `TYPE_MOVES` keys `s8`, `s32` and `u32` serve no local in the code

**File:** `tools/reverseapoc/search.py:51-54`
**Issue:** Later-use code. The SUMMARY justifies the typedef keys as spellings "committed C uses for locals". A scan of `src/` finds plain locals of `u8` (2), `u16` (1) and `s16` (33), but none of `s8`, `s32` or `u32`, and the lifter emits none of them.
**Fix:** Drop the three keys and their assertion in `test_type_table_reads_the_local_types_of_our_c`, or keep them with a reason in this REVIEW.

### IN-03: `body_key` leaves out the leading jump table that the head's verdict reads

**File:** `tools/reverseapoc/batch.py:474-481`
**Issue:** `with_relocs` checks a head function through `_head_reloc`, which reads the table span at `_TEXT+0`. That span lies before `d.off`, so neither its bytes nor its fixups are hashed. The docstring's reason for hashing fixups applies equally here. No current move can change a table without changing the body, so this is latent.
**Fix:** Hash the segment bytes and fixups from offset 0 when `table_row` leads the row, or state the assumption in the docstring.

### IN-04: The statement axis reads some declarations as statements

**File:** `tools/reverseapoc/search.py:142-148`, `:207-214`
**Issue:** Proved: `static int k;`, `int (*fp)(int);` and `int a1; int a2;` all fail `_declaration`, so `_is_simple` accepts them and `statement_moves` swaps them. The last form is also invisible to the declaration axis. This only spends budget: a swap with a real statement fails to compile, and a non-exact variant is dropped.
**Fix:** Refuse in `_is_simple` a line that starts with a type specifier, `static` or `extern`.

### IN-05: Local struct members count as locals

**File:** `tools/reverseapoc/search.py:174-179`
**Issue:** Proved: the members of a local `struct { int m; short n; } s;` are returned as declarations, so type and declaration moves change the struct's layout. `src/` holds no such local today.
**Fix:** Skip lines inside a block whose `{` line has a `struct` or `union` head.

### IN-06: A base that fails to compile is silent in the verb's output

**File:** `tools/reverseapoc/cli.py:1259-1267`
**Issue:** Proved on stubs: with every compile failing, the run spent 74 compile jobs and reported `score 0.0`. The reason exists only as `key` in `results.jsonl`. `reverseapoc judge` prints `COMPILE FAILED` for the same case.
**Fix:** Print the winner's `key` when no record has `compiled` true.

### IN-07: The row's output is cleared before the last refusals

**File:** `tools/reverseapoc/search.py:468-471`
**Issue:** `test_a_missing_function_leaves_the_row_output_alone` shows the intent to refuse before clearing, but `_cells` runs after `shutil.rmtree`, and the compiler gate after that. A rule or gate error destroys the previous `best.c`.
**Fix:** Compute `cells` before the `rmtree`.

### IN-08: `bodies` counts failures as bodies

**File:** `tools/reverseapoc/search.py:91`, `:362-365`, `:455`
**Issue:** `len(run.verdicts)` includes the `"not defined"` key and each `"no object: <path>"` key, while the field says "distinct function bodies judged". The path in the second key also means that failure never dedupes.
**Fix:** Count only keys from `body_key`, or reword the field and the verb's output.

### IN-09: The failure branch of `_verdict` has no test

**File:** `tests/test_search.py:87`
**Issue:** `Stubs` always returns a `Path` from `function_body`, so `isinstance(body, str)` at `search.py:362` is never true in the suite. The docstring's claim about failure keys is untested.
**Fix:** Add a stub case where `function_body` returns `"not defined"`, and assert that the record scores 0 and the search continues.

### IN-10: Depth is not followed in a body with no `sub esp`

**File:** `tools/reverseapoc/batch.py:338-341`
**Issue:** Proved: in `push ebx; mov eax, [esp + 8]; push eax; mov eax, [esp + 0xc]; call`, one slot reads as both 8 and 0xc, because `frame` stays None and `_depth_after` never runs. 38 game rows have `[esp` operands and pushes with no `sub esp`, and the first one found is an interrupt handler, so the effect is small. The known limit in `slot_map`'s docstring does not mention it. The SUMMARY records the related first-`sub esp`-only limit.
**Fix:** Add this case to the docstring's known limit, or start depth at the first non-prologue push.
