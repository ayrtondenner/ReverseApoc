<objective>
This is a gap closure. Spike 011 showed that most Tier 1 rows that end in filler fail `check` for one reason. Their
original row ends in up to 15 bytes of linker alignment filler, because each original object held one function and
the linker aligned each object's `_TEXT` to 16. Our object has no such filler: in a unit, the next function is an
`INCLUDE_ASM` stub that emits nothing. `relocs._length` requires our size to equal the row, so it refuses C that is
byte-correct. Tier 1 stands at 943 members and 63 matched.

The owner ruled option A (2026-11-01, kickoff of this gap): `check` accepts that filler under exactly the five
conditions of the design. The guards are the negative tests and the whole-EXE SHA-1. This plan unblocks:
- 32 converter rows and 1 agent row (tacp 0x0006BEE0) that need no flag change. They land in Task 2a, which the
  orchestrator runs after this plan is on main.
- the 13 converter rows and 5 agent rows that also need a per-unit `-oneatx` cell. These go through 07-48c, then
  Task 2b, and each needs the owner's D-12 approval.

What the code does today (read at feac4c9; executors re-verify by name, line numbers are hints):
- `Defined.size` is omf2elf's `_code_end`: our own trailing eax-only filler after a terminal instruction is already
  trimmed. So the shortfall is original filler that we do not emit.
- `relocs.check_function` returns early when `_length` yields a problem (relocs.py ~L366-368). `_bytes`,
  `_our_fixups` and `_reverse_coverage` already work over `pair.size`, and `theirs` holds the LE fixups that overlap
  the whole row.
- `check.compare_bytes` counts `abs(len(ours) - length)` as differing (check.py ~L717-727).
- `land.build_patch` refuses `len(ours) != end - start` (land.py ~L99-102), and its field-copy loop clips at the row
  end. `splice()` accepts patches of any length.
- `FunctionCheck.ok` is objdiff == 100 and reloc.ok and bytes_ok. target.py `_row_symbol` sizes each target symbol to
  the full row, so objdiff on a short public is UNMEASURED. objdiff-cli runs only in the container. This plan
  measures it before it decides anything about the target (Task 3, two written branches).
- `batch.is_alignment_filler` (any register, regexes on op_str) and `filler_tail` exist. The predicate moves into
  x86.py on capstone operand detail, and batch keeps its name as a delegate.

Decisions taken here, with their reasons:
- **The reason is appended, never replacing the prefix.** Attempt keys and the docs read the
  `length differs: ours N bytes, original M bytes` prefix, so a refusal keeps it and adds `; <reason>`. Reasons name
  VAs, counts and mnemonics only, never operands or bytes.
- **The negatives are RED because they assert the reason text.** HEAD refuses every length difference with the bare
  prefix, so a refusal test that only checked "refused" would pass on HEAD and prove nothing. Each negative asserts
  the reason of the condition that must refuse it, which also proves the order of the conditions. After GREEN, a
  mutant run disables each condition in turn and shows its negative failing (48-mutants.txt).
- **`FunctionCheck.filler` is a property that reads `reloc.filler`**, so the count has one source, the verdict that
  land also reads.
- **Our own sizes do not move.** omf2elf keeps the eax-only `is_filler`. `is_alignment_filler` is a new, separate
  predicate, used only to read the original's tail (and by batch).
- **The deferred D-50 idea is untouched.** The filler lies inside the function's own functions.csv row, so no
  progress or coverage figure changes. D-50 is about bytes outside every row.
- **sweep is not edited.** It calls the shared check_function, so its byte compare follows the rule. If Task 3 takes
  branch B, its separately cut target stays a full row, so a sweep cell on a filler row may still rank below 100.
  This is recorded, and nothing is gated on it.
